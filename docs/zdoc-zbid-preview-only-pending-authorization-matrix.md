# ZDoc-ZBid preview-only pending authorization matrix

## 1. 当前阶段结论

截至本阶段：

- ZDoc-ZBid preview-only 对接闭环已完成。
- small-scale trial 已完成。
- observation docs-only 优化已完成。
- 当前仍未开放正式生成、正式 evidence、评分依据写入、DOCX 导出、review/apply、ZBid 写回。
- 当前仍未进入扩大试用、真实业务联调、50 人正式部署设计。

本文档只整理待授权事项的归类、排序、风险和前置条件，不代表已授权执行任何后续动作。

- 是否需要 endpoint 调用

- 是否涉及试用扩大

- 建议前置条件
- 当前建议优先级：高 / 中 / 低
- 当前是否已授权
- 当前是否已执行
- 是否允许进入正式链
- 是否允许写 output/job/export

## 4. 继续禁止事项

在后续任何事项获得明确授权前，继续禁止：

- 调用 `/generate`。
- 调用 `/export_docx`。
- 调用 `/review/apply`。
- 触发 ZBid 写回。
- 生成 DOCX。
- 写入 `output/job/export`。
- 将 preview-only 结果作为 evidence。
- 将 preview-only 结果作为评分依据。
- 未授权启动服务、访问端口、调用 endpoint。
- 未授权扩大试用。
- 未授权进入 50 人正式部署设计。

## 5. 优先级建议

- 高优先级：与小范围试用观察项闭环直接相关、且仍不触碰正式链的事项，包括观察项代码优化、UI/文案优化、问题修正授权请求、日志结构增强授权请求、人工复核检查表落地优化。
- 中优先级：扩大试用前置边界设计、扩大试用授权请求、small-scale trial 复验和 cross-system smoke 复验。
- 低优先级：50 人正式部署前置边界设计和 50 人正式部署设计授权请求。

50 人正式部署设计不得排入当前直接执行序列前面。只有在小范围试用、问题清单、必要修正和复验完成后，才适合进入正式部署设计相关授权链路。

## 6. 结论建议

当前最合理的后续工作应优先保持在 preview-only / no-write / no-evidence 范围内，完成观察项闭环与必要复验。

完成观察项闭环和复验后，再考虑扩大试用。

扩大试用完成并处理相关问题后，最后才进入 50 人正式部署设计。

本文档不授权任何代码修改、服务启动、端口访问、endpoint 调用、扩大试用、真实业务联调或正式部署设计。
