# OpenClaw / Zhifei Doc Phase 1B Static Demo Workflow

## Purpose

Phase 1B establishes the no-runtime workflow contract for the sanitized demo project.
It links project registration, P0 readiness, static boundary checks, a planned output
index, and the later runtime or endpoint gate without reading real project material.

## Entry Baseline

- Entry HEAD: `cd8aeace4c59c29c5096d9a9c021bdccd8fe94b9`
- Entry P0 readiness: `PASS_P0_READINESS_STATIC`
- Demo input: `projects/_demo_p0/project.json`
- Held config path: `local-launcher-v1/mock-config.json`
- Held config handling: metadata-only; content remains unread.

## Static Workflow

The Phase 1B workflow is generated by:

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=$PWD python3 scripts/phase1_demo_workflow.py --json
```

The workflow contains these ordered steps:

1. `register_sanitized_project`
2. `prove_p0_static_readiness`
3. `run_static_boundary_checks`
4. `prepare_static_output_index`
5. `handoff_to_runtime_gate`

The first four steps are static-only. The fifth step is intentionally blocked until
a separate runtime or endpoint gate is approved.

## Output Index Rule

Phase 1B does not create generated business outputs. Its output index is a plan:

- sanitized project metadata input;
- P0 static readiness evidence;
- Phase 1B static workflow evidence;
- future runtime output placeholder blocked by the separate runtime or endpoint gate.

`materialized_outputs` must remain empty in this phase.

## Boundary

Allowed:

- Read the sanitized demo project metadata.
- Read ordinary source, docs, tests, and scripts.
- Run unit tests and static CLIs that do not start services.
- Commit local static workflow code, tests, and docs.

Forbidden:

- Runtime startup.
- Launcher execution.
- Endpoint access, including `/health`, `/p0/readiness`, `/openapi.json`, `/list_files`, and `/read_file`.
- Held config content read.
- Real business material content read.
- Secret, token, or private key reads.
- Fetch, pull, merge, push, tag, release, or PR mutation.

## Acceptance

Phase 1B is accepted only when:

- `backend.tests.test_phase1_demo_workflow` passes;
- `backend.tests.test_p0_readiness` still passes;
- `scripts/p0_readiness.py` and `scripts/p0_readiness.py --json` return `PASS_P0_READINESS_STATIC`
  after commit;
- `scripts/phase1_demo_workflow.py --json` returns `PASS_PHASE1B_DEMO_WORKFLOW_STATIC`
  after commit;
- the worktree is clean and forbidden actions remain empty.
