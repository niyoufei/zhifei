# 01-HCX8-FINAL-KG-治理评标门控

## 文件定位

本文件是 HCX8-V21 最终上传包的治理与安徽青天 AI 类人评标门控知识图谱。用于 ChatGPT Knowledge 检索，约束施工组织设计、技术标、审校、压缩和评分适配的事实优先级、证据边界、缺口处理、暗标规则、异常低价规则和自动释放边界。

本文件只提供知识、规则、门控和产物 Schema，不替代项目招标文件、评标办法、监管平台规则或评标委员会判断。

## 01 事实优先级

按以下顺序消费事实：

1. 招标文件、答疑、补遗、澄清、合同条款。
2. 评标办法、评分标准、暗标规则、格式要求。
3. 图纸、设计说明、专项设计、工程量清单、设备表、控制价说明、工程界面。
4. 现行规范、行业标准、地方导则、监管要求。
5. HCX8 知识图谱中的实体、关系、证据锚点、结构化 Schema、行业节点、审校词库、门控和 blocker。
6. 施工组织设计样本和类似工程经验。
7. 用户明确补充的项目事实。
8. 模型推断。

模型推断只能用于组织表达、风险提示、待补项整理和候选措施，不得替代项目事实、评分依据、验收记录、调试记录、参数证据或监管授权。

## 02 证据边界硬规则

| 资料 | 可证明 | 不可证明 |
|---|---|---|
| 工程量清单 | 项目范围、工程量、计价边界 | 已施工、已检测、已验收、已交付 |
| 图纸/设计说明 | 设计要求、构造做法、前置条件 | 完成事实、检测结果、验收结论 |
| 施组样本 | 组织方法和写作参考 | 本项目已批准或已实施 |
| 规范条文 | 控制标准、检验方法 | 本项目参数已确认 |
| 检测/调试/验收条目 | 记录类型和验收路径 | 真实记录已经形成 |
| 设备/系统/平台 | 能力和接口候选 | 已接入、已联调、已投运 |

投标阶段施工组织设计默认使用计划性表达：`拟采用`、`计划配置`、`项目部将`、`中标后经审批实施`、`按招标人和监理要求完善`、`形成记录作为验收依据`。

不得无证据写成完成态：`已完成`、`已验收`、`已投运`、`已移交`、`已形成真实记录`、`已通过平台验收`、`已闭环`。

## 03 必备资料矩阵

| 资料类型 | 缺失动作 | 影响 |
|---|---|---|
| 招标文件、评分办法、评分标准 | 需补充（缺：招标文件和技术文件评分标准） | 不得生成确定性评分响应矩阵 |
| 暗标规则、格式、页数 | 需人工复核（缺：暗标/格式规则） | 不得断言暗标安全 |
| 图纸、清单、工程范围 | 需补充（缺：项目范围/图纸/清单/专业边界） | 不得确认工程对象和专业参数 |
| 项目参数、试验检测、调试验收记录 | 需补充（缺：成员级参数/真实记录/验收资料） | 不得写完成态和验收态 |
| 证据锚点、页码、条款或资料来源 | 需补充（缺：证据锚点/页码/条款） | 不得输出确定性项目事实和参数承诺 |
| 自动推荐/自动否决授权 | 需人工复核（缺：自动释放授权） | 不得输出自动推荐或自动否决 |

资料不足时输出：

| 暂缺信息 | 影响的评分项/评审环节 | 可先行处理 | 必须补充原因 |

## 04 项目画像与专业路由

解析项目时先建立项目画像：

| 字段 | 内容 |
|---|---|
| project_name | 项目名称 |
| section_name | 标段名称 |
| location | 项目地点 |
| project_category | 房建、市政、水利、交通、公路、桥梁、园林、机电、环保、装饰等 |
| evaluation_method | 动态合理价格法、技术评分合理价格法、综合评估法、定性定量评审法或项目自定义办法 |
| ai_review_flag | 是否启用 AI 类人评审/智能辅助评审 |
| blind_bid_flag | 是否暗标 |
| disciplines | 专业范围 |
| activated_industry_nodes | 已被项目资料激活的行业模块节点 |
| evidence_anchor_status | confirmed、missing、candidate、inferred、conflict |
| objectives | 工期、质量、安全、环保、绿色、智慧建造、交付目标 |

未被招标、图纸、清单或项目特征激活的专业节点，只能作为候选库，不得写成本项目确定事实。

## 05 安徽青天 AI 类人评标抽象链路

1. 解析招标文件评审项。
2. 抽取投标文件响应要素。
3. 对章节、表格、图号、页码或证据锚点溯源。
4. 判断完整性、针对性、可实施性和合规风险。
5. 形成 AI 类人评审逻辑论述。
6. 给出辅助评审建议。
7. 影响专家主观评分、技术文件入围、定级、同分排序或评审意见。

施组核心不是写得多，而是让 AI 稳定判断：评分项是否响应、响应在哪里、是否贴合项目、措施是否具体、是否可检查、是否存在漏项矛盾暗标雷同或越权承诺。

## 06 评标办法适配

| 评标办法 | 施组策略 |
|---|---|
| 动态合理价格法 | 重点保证初评合格，无实质性漏项、暗标、格式、工期、质量、安全目标冲突 |
| 技术评分合理价格法 | 重点提高技术文件详细评审得分，每个评分项都有高分理由 |
| 综合评估法 | 技术文件与商务、报价逻辑不矛盾，措施不降低设计标准，不影响报价合理性 |
| 定性定量评审法 | 支撑“好”或最高等级评价，避免落入较好、一般、差 |

无法确认评标办法时，输出 `需补充（缺：评标办法和技术文件评分标准）`。

## 08 初步评审避险

不得出现：

1. 漏写实质性响应。
2. 工期、质量、安全、缺陷责任期、保修、节点目标与招标文件不一致。
3. 项目名称、标段、地点、招标人、建设内容、工程规模错误。
4. 其他项目残留。
5. 暗标身份信息泄露。
6. 格式、页数、字体、行距、目录、图表不符合要求。
7. 明显复制、同错、雷同、模板套话。
8. 降低或改变原设计方案、技术工艺、施工标准。
9. 使用亏本让利、人员闲置、机械闲置、材料自有、类似业绩等作为异常低价理由。
10. 把计划实施写成已完成、已验收、已投运。
11. 把图纸、清单、招标要求写成已施工事实。

## 09 暗标净化规则

暗标项目必须：

1. 不出现投标人名称、简称、商标、Logo。
2. 不出现人员姓名、证书编号、联系方式、地址、邮箱、网址。
3. 不出现企业荣誉、特定业绩、专属工法、专属系统名称等身份暗示，除非招标文件明确允许且属于非暗标部分。
4. 不使用“我公司”“本公司”“我单位”“我司”，统一使用“投标人”“承包人”“项目部”。
5. 页眉页脚、图片水印、图签、文件属性不得暴露身份。
6. 严格遵守暗标格式和页数要求。

暗标风险无法排除时，输出 `需人工复核（缺：暗标身份信息排查）`。

## 10 雷同与模板残留控制

必须检查：

1. 其他项目名称、道路名、河道名、楼栋号、单位名称。
2. 与本项目行业不符的工序。
3. 重复段落或无项目特征的通用套话。
4. 同错、异常一致、格式异常。
5. 企业宣传口径。

降低雷同风险的方法：用项目部位替代通用对象；用评分项原文重构标题；用本项目工期、场地、界面、专业和风险组织章节；用表格压缩通用描述；删除无法支撑评分的套话。

## 11 异常低价与自动释放边界

异常低价解释必须绑定工程量、施工组织、采购计划、资源配置、市场价格、管理措施和成本证据。禁止使用亏本让利、人员闲置、机械闲置、材料自有、类似业绩等不被认可理由。

只有同时满足以下条件，才可输出自动推荐、自动否决或无人化评标释放建议：

1. 招标文件、监管平台或试点规则明确授权。
2. EVAL 关键 blocker 已关闭。
3. 证据审计包完整，包含规则来源、证据锚点、判断路径和人工复核日志。
4. 不涉及证据冲突、暗标泄露、异常低价争议、雷达异常或法定责任争议。

任一条件不满足，输出 `需人工复核`。

## 12 招标解析、证据审计与场景路由集成

### 招标文件解析规则

资料体检按以下分区解析：招标公告/投标邀请、投标人须知、评标办法、合同条款、技术标准和要求、图纸/设计说明、工程量清单、答疑/补遗/澄清。

| 解析对象 | 必提字段 | 缺失动作 |
|---|---|---|
| 项目画像 | 项目名称、标段、地点、项目类别、评标办法、暗标、专业范围、工期质量安全环保目标 | 缺关键字段时输出需补充 |
| 评标办法 | 办法名称、初步评审、详细评审、技术评分项、报价规则、推荐规则 | 缺评分标准时不得生成确定性矩阵 |
| 技术评分项 | 评分项原文、分值/等级、满分关键词、扣分点、否决关联、证据锚点 | 原文不得用同义词替代 |
| 否决项 | 否决原文、触发条件、影响文件、风险等级、关闭动作 | R0/R1 未关闭不得最终化 |
| 暗标格式 | 身份禁写、页数、字体、行距、页眉页脚、图表、文件属性 | 缺规则时需人工复核 |
| 图纸清单对象 | 工程对象、图号/清单项、可证明事项、不可证明事项、激活行业节点 | 不证明已施工或已验收 |
| 答疑补遗 | 修改对象、原要求、修改后要求、影响评分项、处理动作 | 后发正式资料优先 |

### 项目级关键词动态增强门控

新项目资料包进入解析后，必须同步生成 `项目级关键词覆盖矩阵`，将招标文件、评标办法、答疑澄清、补遗变更、工程量清单、图纸、设计说明、勘察资料、踏勘资料和技术标准中的关键词转化为可审计、可追溯、可写入正文的结构化输入。

| 门控项 | 通过条件 | 失败动作 |
|---|---|---|
| 触发完整性 | 任一项目资料上传后已触发关键词动态增强 | 标 R1/R2，补生成项目级关键词覆盖矩阵 |
| 来源可追溯 | 每个关键词有来源文件、页码、条款、图号或清单编号 | 标需补充，不得写成确定事实 |
| 评分项优先 | 评分标准、扣分项、页数限制、AI 辅助评审要求已标高权重 | 重新解析评标办法和评分标准 |
| 答疑覆盖 | 答疑、澄清、补遗、变更覆盖原招标文件旧关键词 | 标 conflict，按后发正式资料消解 |
| 工程对象细化 | 清单、图纸、招标范围中的主要对象被细化到子目、构造或部位 | 不得只写泛化工程名称 |
| 参数审计 | 材料、规格、厚度、粒径、强度、渗透系数、检测标准有来源 | 缺来源时写需补充 |
| 空泛词降级 | 高度重视、科学组织、确保顺利、加强管理等未被提升为高权重 | 自动剔除或降为低权重 |

### 证据锚点和参数审计

确定性事实必须绑定 `source、page、clause、record_id、fact_status、usable_scope`。证据状态使用 confirmed、missing、candidate、inferred、conflict。

| 审计对象 | 通过条件 | 失败动作 |
|---|---|---|
| 项目事实 | 来源、页码/条款、可证明事项明确 | 标需补充或需人工复核 |
| 参数承诺 | 有来源、单位、对象、检测方法、记录名称 | 降级、删除或标需补充 |
| 完成态表达 | 有真实记录或验收资料 | 无记录时改为计划性表达 |
| 冲突资料 | 已按答疑补遗和事实优先级消解 | 输出冲突表和需人工复核 |

### 评标办法场景路由

| 评标场景 | 策略重点 | 阻断信号 |
|---|---|---|
| 动态合理价格法 | 初评合格、实质响应、暗标格式、工期质量安全一致 | 废标条款、暗标泄露、目标冲突 |
| 技术评分合理价格法 | 逐项覆盖评分项、关键词命中、工程对象、措施资源验收闭环 | 缺技术评分标准、评分项漏项 |
| 综合评估法 | 技术、商务、报价一致，不降低设计和合同要求 | 技术泄露商务身份、报价施工逻辑矛盾 |
| 定性定量评审法 | 支撑“好/优”等最高等级评价，避免空泛 | 缺等级标准、无措施无记录 |
| 异常低价说明 | 工程量、采购、资源、市场、成本证据链 | 亏本让利、闲置、自有材料、类似业绩 |
| 自动释放/无人化 | 授权、证据包、审计日志、人工复核路径 | 无授权或任一关键 blocker 未关闭 |
