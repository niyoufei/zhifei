# 03-HCX8-FINAL-KG-生成流水线自检雷达

## 文件定位

本文件是 HCX8-V21 最终上传包的生成流水线、自检雷达、参数门控、V9 节点补强和 GPT 配置验收知识图谱。用于 ChatGPT Knowledge 检索，确保 GPT 按资料体检、评分项解析、对象绑定、章节装配、证据门控、扣分雷达、最终输出的流程生成施工组织设计。

## 01 一键生成流水线

### Step 0 资料体检

| 资料 | 缺失动作 |
|---|---|
| 招标文件、评标办法、评分标准 | 需补充（缺：招标文件和技术文件评分标准） |
| 暗标规则、格式、页数 | 查规则占位，输出需人工复核 |
| 图纸、清单、工程范围 | 需补充（缺：项目范围/图纸/清单/专业边界） |
| 项目参数、试验检测、调试验收记录 | 需补充（缺：成员级参数/真实记录/验收资料） |
| 自动推荐/自动否决授权 | 无授权则禁止自动释放 |

资料体检必须先调用 `01-HCX8-FINAL-KG-治理评标门控.md` 中的招标解析集成规则，按招标公告、投标人须知、评标办法、合同条款、技术标准、图纸、清单、答疑补遗分区解析，并形成项目画像、评分项、否决项、暗标格式和工程对象证据锚点。

新项目创建或上传招标文件、答疑澄清、补遗变更、工程量清单、图纸、设计说明、勘察资料、现场踏勘资料、技术标准或评标办法时，必须立即调用 `13-HCX8-FINAL-KG-AI评标关键词强化库.md` 的 `关键词动态增强规则（Project Keyword Dynamic Enhancement Rule）`，生成 `项目级关键词覆盖矩阵`。未生成该矩阵前，不得直接进入施工组织设计正文。

### Step 1 评标办法与评分项解析

1. 用 `01-HCX8-FINAL-KG-治理评标门控.md` 的评标办法场景路由识别评标办法和审查场景。
2. 提取评分项原文、分值、满分关键词、扣分点和否决项。
3. 从项目资料包提取项目基础关键词、评分关键词、工程对象关键词、施工工艺关键词、材料与参数关键词、风险控制关键词、验收检测关键词和答疑澄清关键词。
4. 对答疑、澄清、补遗、变更中修改的评分标准、清单子目、工期、资格、材料、技术参数或报价要求，按后发正式资料优先原则覆盖原关键词，并标记为高优先级关键词。
5. 用 `02-HCX8-FINAL-KG-评分词库章节模板.md` 的评分同义词与标题召回补充同义词、AI 识别词、标题命中词和风险召回词。
6. 用 `13-HCX8-FINAL-KG-AI评标关键词强化库.md` 建立项目级关键词覆盖矩阵和 AI 评标关键词覆盖矩阵，确认矩阵、标题、段首、正文、表格和收口命中要求。
7. 生成评分响应矩阵初稿。

### Step 2 工程对象绑定

1. 用系统族、构件族、工序族和接口族绑定工程对象。
2. 用 `06-HCX8-FINAL-KG-行业模块库.md` 确认专业候选、行业对象、关键工序、验收记录和行业错配风险。
3. 多专业项目生成对象界面矩阵。
4. 项目级关键词覆盖矩阵中的主要工程对象必须至少进入工程概况、重点难点、施工方案、质量控制、安全控制、进度组织或总平面布置之一。
5. 用 V9 补强层补充节点正文、参数和证据需求。

### Step 3 章节装配

1. 用章节模板库生成章节。
2. 每个章节必须有四步闭环。
3. 用 `09-HCX8-FINAL-KG-标准产物模板库.md` 统一资料体检、项目画像、矩阵、正文、审计、整改和收口格式。
4. 每个章节必须包含对象、措施、标准、记录、blocker。

### Step 4 证据与规则门控

1. 用证据边界检查越权事实。
2. 用 `01-HCX8-FINAL-KG-治理评标门控.md` 的证据锚点、证据状态、冲突消解和参数审计规则检查越权事实。
3. 用 EVAL 门控检查青天 AI 评标边界。
4. 用规则占位和冲突处理检查缺规则和冲突。
5. 用参数门控检查参数来源。
6. 执行技术标准校核：优先读取项目技术标准、图纸说明和招标技术要求；项目资料已有参数时以项目资料为准；确需补充标准参数时优先检索知识库内现行有效规范，具备联网能力时检索官方或权威来源；无法确认来源的参数写“按设计文件及现行规范要求执行”并标 `需核实`。

### Step 5 扣分雷达自检

1. 扫描 R0/R1/R2/R3 风险。
2. 调用 `14-HCX8-FINAL-KG-关键词回归样例与使用清单.md` 扫描暗标、雷同、项目残留、行业错配、越权承诺和反例坏样本。
3. 对照空话、暗标、完成态、参数虚构、行业错配、评分漏项、异常低价、自动释放和压缩误删反例。
4. 调用 `13-HCX8-FINAL-KG-AI评标关键词强化库.md` 执行关键词命中、自检和反堆砌检查。
5. 检查项目级关键词覆盖矩阵是否已被正文调用：评分关键词必须覆盖评分章节，工程对象必须绑定章节，工艺关键词必须写成工序流程、操作措施、质量控制、验收标准和留痕资料，风险关键词必须写成风险识别、应对措施、检查频次、责任人和留痕资料。
6. 检查答疑澄清覆盖关键词是否优先使用，禁止继续引用被澄清替代的旧内容。
7. 检查空泛通用词是否被错误提升为高权重；高度重视、科学组织、确保顺利、加强管理等只允许低权重或剔除。
8. 定稿前调用 `14-HCX8-FINAL-KG-关键词回归样例与使用清单.md` 执行关键词回归和检查清单。
9. R0 和 R1 未关闭前不得输出最终版。
10. R2 和 R3 可自动整改后输出。

### Step 6 最终输出

按 `09-HCX8-FINAL-KG-标准产物模板库.md` 输出评分响应矩阵、项目级关键词覆盖矩阵、AI 评标关键词覆盖矩阵、施工组织设计目录、正文、表格和记录包清单、证据审计摘要、参数审计摘要、关键词自检结果、反例审校摘要、风险与 blocker 清单、需补充资料清单、暗标与格式复核提示、青天 AI 可抽取性自检结果。审校、净化或压缩任务同时输出整改前后对照。

## 03 扣分雷达

### 自检总规则

1. 每个评分项必须有章节标题命中。
2. 每个章节必须有“目标任务、风险难点、执行措施、验证检查”四步闭环。
3. 每个评分项至少绑定一个工程对象。
4. 每个工程对象至少有措施、资源、标准、记录或验收闭环。
5. 每个数值、算法、阈值和性能承诺必须有来源；无来源则写需补充。
6. 暗标项目不得出现身份线索。
7. 行业模块必须由项目资料激活，未激活专业不得写成确定事实。
8. 不得出现保证满分、必然加分、自动推荐、自动否决等越权表达。

### 自检矩阵

| 检查项 | 满分导向标准 | 扣分/风险信号 | 修正动作 |
|---|---|---|---|
| 评分项覆盖 | 评分项原文全部进入矩阵和章节 | 有评分项无章节、章节标题不含关键词 | 新增章节或改标题 |
| 项目级关键词覆盖 | 新项目资料包已生成项目级关键词覆盖矩阵，关键词均有来源文件、页码或条款 | 只调用通用行业知识、关键词无来源、答疑覆盖未标记 | 重新解析项目资料包并生成覆盖矩阵 |
| 答疑澄清覆盖 | 后发答疑澄清、补遗变更覆盖原关键词 | 继续引用旧工期、旧清单、旧评分标准或旧参数 | 按答疑澄清重建关键词和章节 |
| 段首响应 | 每段开头直接回应评分项 | 长段落开头讲背景 | 改为“本节响应……” |
| 工程对象绑定 | 每个评分项绑定工程对象/系统/工序 | 只有管理口号 | 增加对象和专业节点 |
| 四步闭环 | 目标、风险、措施、验证齐全 | 只有措施无验证 | 按四步模板补齐 |
| 参数来源 | 参数有招标/图纸/规范/记录来源 | 直接承诺百分比、阈值、排名 | 标需补充 |
| 技术标准校核 | 技术标准、图纸说明、招标技术要求优先；无来源参数标需核实 | 虚构厚度、强度、间距、坡度、材料型号、检测频次 | 删除或改为按设计文件及现行规范要求执行 |
| 证据闭环 | 记录包、验收、移交资料明确 | 写已验收但无记录 | 降级为拟形成并列记录包 |
| 行业激活 | 行业对象、工序由项目资料激活 | 房建、市政、水利等行业错配 | 删除错配内容或标需补充 |
| 暗标安全 | 无身份、业绩、单位归属、特定企业 | 我公司、业绩、专利、人员单位 | 删除或泛化 |
| 异常低价 | 不使用禁用解释 | 亏本、闲置、自有材料、类似业绩 | 改为成本证据链 |
| 自动释放 | 无授权不自动推荐/否决 | 写自动推荐、自动否决 | 改为需人工复核 |
| 空话套话 | 责任、动作、参数、记录明确 | 加强管理、确保质量、严格落实 | 改写为责任主体+动作+参数+记录 |
| 页数格式 | 格式和页数按招标要求 | 缺页数、字体、目录规则 | 查规则占位 |
| 冲突处理 | A_primary 覆盖经验和模板 | 通用模板覆盖招标条款 | 按冲突规则消解 |

### 风险等级

| 等级 | 触发条件 | 输出动作 |
|---|---|---|
| R0 致命 | 废标条款、暗标身份泄露、自动否决越权、评分办法缺失 | 停止最终化，输出需人工复核 |
| R1 高风险 | 评分项漏项、无工程对象、无证据闭环、关键参数无来源 | 输出整改清单，补齐后再生成 |
| R2 中风险 | 空话套话、章节标题弱、长段落不可抽取 | 触发重写 |
| R3 低风险 | 表述重复、格式可读性弱、章节排序不优 | 压缩和优化 |

## 06 参数门控

V9 参数、算法、阈值、格式标准和性能表达只可作为候选提示，并按 `01-HCX8-FINAL-KG-治理评标门控.md` 的证据锚点和参数审计规则执行审计。所有数值承诺必须满足：

1. 有招标文件、图纸、规范、清单、设备表、检测记录或用户明确证据。
2. 有单位、阈值、适用对象、检测方法和记录名称。
3. 与项目工程对象和评分项绑定。
4. 缺来源时写 `需补充（缺：参数来源/阈值/记录）`。

禁止无来源承诺：效率提升百分比、质量问题降低比例、工期压缩比例、平台准确率、自动识别率、能耗降低率、碳减排量、排名、必然加分。

## 07 V9 原生节点补强使用规则

V9 原生 JSON 已转化为 112 个节点补强卡。使用规则：

1. `premium_direction` 和 `response_template` 只能作为候选写作素材。
2. 使用 V9 模板前必须替换为项目评分项、工程对象、项目证据、成员级参数和记录包。
3. `competitor_shield`、`trap_logic`、`target_rival` 只能用于内部审校，禁止进入暗标技术文件或正式投标正文。
4. `qt_score_booster` 只能提示政策和评分关注点，不得写成必然加分、满分或排名承诺。
5. V9 算法、阈值、性能承诺和平台能力必须回到项目证据；缺证时写 `需补充`。

## 11 输出收口

1. 已使用的关键 HCX8 节点或知识文件。
2. 已覆盖的评分项。
3. 证据锚点状态和参数审计结果。
4. 反例审校命中和整改状态。
5. 已关闭的 blocker。
6. 仍需补充的资料。
7. 需人工复核的事项。
8. 扣分雷达 R0/R1/R2/R3 结果。
9. 可直接进入正文或矩阵的内容范围。
