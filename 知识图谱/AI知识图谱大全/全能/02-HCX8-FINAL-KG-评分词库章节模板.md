# 02-HCX8-FINAL-KG-评分词库章节模板

## 文件定位

本文件是 HCX8-V21 最终上传包的评分项词库、章节映射、施组模板和 AI 可抽取写作知识图谱。用于 ChatGPT Knowledge 检索，支撑施工组织设计生成、技术标评分响应、正文编制、页数压缩和行业模块派生。

## 01 评分响应矩阵

正式编制前必须建立评分响应矩阵：

```markdown
| 序号 | 评分项原文 | 分值/等级 | 满分关键词 | 招标证据 | 证据状态 | 项目特征 | 工程对象 | 响应章节 | 施工措施 | 资源保障 | 验收闭环 | 风险/扣分点 | 修正动作 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
```

矩阵规则：

1. 评分项原文不得随意改写。
2. 章节标题应尽量包含评分项关键词。
3. 每个评分项至少有一个可抽取响应句。
4. 每个评分项至少绑定一个工程对象或项目特征。
5. 每个评分项至少形成“措施 + 资源 + 标准 + 记录/验收”的闭环。
6. 每个评分项标注证据状态：confirmed、missing、candidate、inferred 或 conflict。
7. 缺少项目证据时标注 `需补充`，不得虚构。
8. 新项目资料包已生成 `项目级关键词覆盖矩阵` 时，评分响应矩阵必须调用其中的评分关键词、工程对象关键词、施工工艺关键词、材料参数关键词、风险关键词、验收检测关键词和答疑澄清覆盖关键词。
9. 答疑澄清覆盖关键词优先于原招标文件旧关键词；被覆盖旧内容不得继续进入评分响应矩阵。

## 03 通用章节结构

若招标文件未规定固定结构，采用以下结构；若评分项顺序不同，按评分项顺序重排。

1. 评分响应总表。
2. 工程理解与重难点识别。
3. 施工部署与组织管理。
4. 施工总平面布置。
5. 主要分部分项工程施工方案。
6. 工期计划与节点保障。
7. 劳动力、机械、材料和资金资源保障。
8. 质量管理体系与关键质量控制。
9. 安全生产、危大工程和应急管理。
10. 文明施工、环境保护和绿色建造。
11. BIM、智慧工地、智能建造和科技创新。
12. 季节性施工、交通组织、成品保护和协调配合。
13. 资料管理、竣工验收、移交和保修配合。

## 04 四步闭环写作

每个评分项正文必须包含：

1. 目标任务：直接响应评分项原文，说明要解决什么评分要求。
2. 风险难点：绑定项目部位、工序、界面、现场条件、工期节点和风险。
3. 执行措施：写清对象、动作、责任、频次、标准、资源和记录。
4. 验证检查：写清检查方式、验收标准、记录名称、整改闭环和资料成果。

项目级关键词调用要求：

| 关键词类别 | 正文落点 | 表达方式 |
|---|---|---|
| 评分关键词 | 评分响应矩阵、标题、段首、表格和收口 | 保留评分项原文、分值、扣分点和章节映射 |
| 工程对象关键词 | 工程概况、重点难点、施工方案、质量安全进度章节 | 写具体部位、清单子目、图纸构造或专业界面 |
| 施工工艺关键词 | 主要施工方案、关键工序、专项措施 | 工序流程 + 操作措施 + 质量控制 + 验收标准 + 留痕资料 |
| 材料与参数关键词 | 材料控制、工艺控制、质量验收 | 参数 + 来源 + 检测方法 + 记录名称；缺来源写需补充 |
| 风险控制关键词 | 重难点、安全、环保、总平面、交通组织 | 风险识别 + 应对措施 + 检查频次 + 责任人 + 留痕资料 |
| 验收检测关键词 | 质量、资料归档、验收移交 | 检测指标 + 验收方法 + 资料归档 + 影像留痕 |
| 答疑澄清关键词 | 对应被修改章节和收口自检 | 后发正式资料优先，覆盖旧关键词并标记来源 |

标准段落模板：

```text
本节针对招标文件“【评分项原文】”要求进行响应。结合本项目【工程对象/施工部位/现场条件/工期节点】，项目部拟采用【施工方法/组织措施】，配置【岗位/班组/机械/材料/检测资源】，按照【规范/验收标准/招标要求】实施过程控制，并形成【检查记录/验收资料/整改闭环】。该安排覆盖【质量/进度/安全/环保/绿色/智慧建造】要求，具备完整性、针对性、可实施性和可追溯性，可支撑本评分项的高分评价理由。
```

## 05 八类章节模板

### HCX8-TPL-001 施工总体部署

- required_inputs: 项目范围、单位工程、专业工程、施工阶段、现场条件、总工期、关键节点。
- required_outputs: 总体部署、区段划分、施工顺序、平面布置、资源匹配、验收准出。

正文结构：目标任务响应总体部署评分项；风险难点识别工程范围、图纸清单、现场边界和接口缺失风险；执行措施按单位工程和专业工程划分区段，以关键线路组织穿插施工，配置人员、机械、材料、检测资源；验证检查通过进度网络图、平面布置图、资源计划和接口矩阵复核。

### HCX8-TPL-002 主要施工方案

- required_inputs: 图纸、清单、设计说明、专项方案、规范、关键参数。
- required_outputs: 工艺流程、控制点、资源配置、参数标准、检验验收。

正文结构：目标任务响应主要施工方案评分项；风险难点识别质量、安全、接口和参数缺失风险；执行措施由责任岗位组织班组、机械、材料，按工艺流程控制参数、频次和允许偏差，设置首件、样板、旁站、隐蔽验收；验证检查通过检验批、试验报告、隐蔽验收、检测记录和整改复查闭环。

### HCX8-TPL-003 质量保证措施

- required_inputs: 质量目标、验收标准、检测项目、记录包。
- required_outputs: 质量控制点、检验检测计划、整改闭环、资料归档。

正文结构：围绕材料进场、过程控制、检验检测、验收移交建立质量闭环；控制材料复检、隐蔽工程、关键参数和验收资料；由质量负责人、试验员、专业工程师按频次检查对象并形成记录；以检验批、试验报告、隐蔽验收、整改复查、竣工资料验证。

### HCX8-TPL-004 安全文明施工

- required_inputs: 危险源清单、危大工程清单、应急预案、文明施工要求。
- required_outputs: 风险分级、责任岗位、巡检频次、隐患整改、应急演练。

正文结构：对危险源、危大工程、文明施工对象建立分级管控和隐患闭环；风险包括坍塌、高处坠落、机械伤害、临电、消防、扰民等；由安全负责人组织教育交底、专项检查、旁站监护、应急演练；通过安全交底、巡检记录、隐患整改通知、复查记录、演练记录闭环。

### HCX8-TPL-005 工期进度与资源保障

- required_inputs: 总工期、节点工期、网络计划、资源计划、材料供应计划。
- required_outputs: 关键线路、资源峰值、供应保障、纠偏机制。

正文结构：以总工期和节点工期为约束，建立关键线路、资源保障和纠偏机制；识别关键线路延误、资源峰值不足、材料供应滞后和交叉作业冲突；编制网络计划、横道图，配置劳动力、机械、材料、检测资源，设置预警阈值和纠偏动作；通过周计划、月计划、进度报表、资源到位记录、纠偏记录复核。

### HCX8-TPL-006 绿色环保与文明协调

- required_inputs: 周边敏感点、环保要求、绿色施工目标、交通组织要求。
- required_outputs: 污染控制、绿色指标、周边协调、投诉处置。

正文结构：围绕扬尘、噪声、废水、固废、节能、周边协调建立绿色施工闭环；识别扬尘超标、噪声扰民、废水外排、交通冲突；由环保负责人按频次监测指标，配置喷淋、覆盖、沉淀、隔声、回收措施，并建立公告和投诉响应机制；通过监测记录、台账、照片、投诉处置记录、绿色指标统计验证。

### HCX8-TPL-007 BIM 智慧工地与数字交付

- required_inputs: BIM 要求、智慧工地条款、平台接口、交付格式、运维需求。
- required_outputs: 使用场景、数据来源、接口记录、平台验收、数字交付。

正文结构：将 BIM、智慧工地、数字孪生、AI 用于深化设计、进度、质量、安全、资料交付；识别模型与现场脱节、数据无来源、平台未验收、接口未打通；建立模型、数据、平台、接口清单，按数据刷新周期、责任岗位、输出记录运行；通过模型审查记录、平台日志、接口联调记录、数字交付清单验证。

### HCX8-TPL-008 资料归档、验收移交与后期服务

- required_inputs: 验收要求、归档目录、移交条款、维保要求。
- required_outputs: 记录包、移交清单、培训回访、维保响应。

正文结构：建立从过程资料、验收资料到移交维保的交付闭环；识别资料缺项、验收记录不完整、移交责任不清、维保响应无时限；按专业、系统、验收批建立资料目录，由资料员、专业工程师、项目负责人分阶段收集、复核、归档和移交；以资料清单、验收单、移交单、培训记录、回访记录为证据。

## 06 AI 可抽取写作规则

1. 使用评分项原文或近似关键词做标题。
2. 每段开头直接回应评分项。
3. 一段只解决一个评分点或一个工程对象。
4. 每项措施写清对象、动作、责任、频次、标准、记录。
5. 多用表格承载密集证据。
6. 避免评分点隐藏在长段落中。
7. 避免空泛承诺、营销话术和百科式材料。
8. 所有 `需补充` 事项保持占位，不编造。

## 07 高分理由

每个评分项至少生成三类高分理由：

1. 完整性理由：覆盖评分要求、工程对象、工序、资源、验收和风险。
2. 针对性理由：对应本项目部位、专业、工况、节点、界面和风险。
3. 可实施性理由：有岗位、班组、机械、材料、检查频次、验收标准和成果文件。

句式：

```text
本节围绕【评分项名称】设置【措施类别】，针对【项目具体难点】提出【具体方法】，并通过【资源配置/过程检查/验收记录/整改闭环】形成可实施、可检查、可追溯的控制链，可满足招标文件关于【质量/工期/安全/环保/技术先进性】的要求，具备支撑高分评价的充分理由。
```

不得使用：高度重视、严格落实、确保万无一失、充分发挥优势、具有丰富经验、按规范执行但无具体措施。

## 08 通用质量安全进度环保写法

| 方向 | 必须写清 |
|---|---|
| 质量 | 质量目标、控制点、样板或首件、检验批、隐蔽验收、旁站检查、允许偏差或验收依据、整改闭环和资料成果 |
| 安全 | 危险源、风险等级、专项方案、交底教育、监测预警、应急处置 |
| 进度 | 总工期、关键节点、关键线路、资源投入、穿插逻辑、纠偏机制，不以降低质量安全为代价赶工 |
| 环保文明 | 扬尘、噪声、污水、固废、车辆冲洗、道路保洁、夜间施工、生态和水土保持 |

## 09 BIM、智慧工地与绿色建造

涉及 BIM、智慧工地、智能建造、绿色建材、绿色施工、科技创新时，不得只写概念。必须写成应用闭环：

| 应用项 | 应用部位 | 管理动作 | 数据/成果 | 检查频次 | 评分支撑 |
|---|---|---|---|---|---|

字段要求：应用场景、数据来源、管理动作、输出成果、检查频次、对质量/进度/安全/环保的具体价值。

## 10 行业模块接入

遇到房建、市政、水利、交通、公路、桥梁、园林、机电、环保、装饰等行业时，优先检索 `06-HCX8-FINAL-KG-行业模块库.md` 并加载对应专业知识包。行业模块必须提供：

| 字段 | 内容要求 |
|---|---|
| industry_name | 行业名称 |
| project_objects | 工程对象 |
| key_processes | 关键工序 |
| scoring_keywords | 常见评分关键词 |
| quality_controls | 质量控制点 |
| safety_controls | 安全与危大控制 |
| progress_controls | 工期组织逻辑 |
| environmental_controls | 环保、水保、文明施工 |
| smart_green_controls | BIM、智慧、绿色建造 |
| acceptance_records | 验收和资料成果 |

没有行业模块时，可以使用通用施工逻辑，但必须避免编造专业参数。

行业模块激活规则：

1. 招标文件、图纸、清单、设计说明、工程范围或用户明确资料至少命中一类激活信号。
2. 行业模块中的工程对象、关键工序、记录包和风险只能作为候选，必须绑定项目证据后进入正文。
3. 多专业项目必须生成对象界面矩阵，说明上游条件、下游交接、关键风险和验收记录。
4. 行业错配触发 R1；未关闭前不得输出最终版。

## 11 页数压缩规则

压缩时保留：评分项原文或关键词、实质性响应、否决项避险、工程对象、关键证据、证据状态、工期质量安全目标、验收闭环、暗标合规内容、blocker 和关闭动作。

压缩时删除：无评分功能背景、重复规范表述、企业宣传、重复套话、无评分项对应内容、可合并进表格的长段落。
