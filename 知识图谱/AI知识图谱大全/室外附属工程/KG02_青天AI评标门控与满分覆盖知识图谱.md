## 1 青天 AI 类人评标抽象链路

1. 解析招标文件、评标办法、技术评分项、暗标规则和格式要求。
2. 抽取投标文件的响应章节、评分关键词、工程对象、工艺流程、参数标准和证据留痕。
3. 定位章节标题、节点名称、表格字段、图号页码、资料锚点或附件索引。
4. 判断完整性、针对性、可实施性、合规风险、证据边界、风险闭环和整改复核能力。
5. 形成类人评审理由、扣分风险、补强建议、专家关注点和复核意见。
6. 影响专家主观评分、技术标定级、入围判断、同分排序或评审意见表达。

因此，施组必须让 AI 稳定识别：评分项是否被响应、在哪里响应、是否贴合本项目、措施是否具体可检查、参数是否有依据、验收是否有标准、资料是否可追溯、是否存在漏项、暗标、雷同、越权或否决风险。

### 1.1 AI 可识别表达主链

每个评分节点、工序节点和风险节点优先采用“问题—措施—参数—验收—证据”表达：

```text
问题：识别【评分项/工程对象/风险难点】。
措施：由【责任主体】按【关键工序/控制措施】实施。
参数：写明【控制目标/质量标准/检查频次/资源配置/时间节点】，无依据时标“待确认”。
验收：采用【验收方法/检测报告/隐蔽验收/整改复核/联合验收】闭环。
证据：形成【旁站记录/检查记录/试验报告/影像资料/会议纪要/资料归档】留痕。
```

禁写仅有“高度重视、加强管理、严格落实、确保万无一失、按规范执行”等空泛表达；必须落到工程对象、工序、责任主体、检查频次、验收方法和留痕资料。

## 2 Fail-Fast 门控

| 场景 | 必须输出 |
|---|---|
| 缺招标文件或技术文件评分标准 | 需补充（缺：招标文件和技术文件评分标准） |
| 缺图纸、清单、工程范围或专业边界 | 需补充（缺：项目范围/图纸/清单/专业边界） |
| 缺暗标规则、格式、页数、签章上传规则 | 需人工复核（缺：暗标/格式/平台规则） |
| 涉及法定责任、异常低价、自动否决、雷达异常、证据冲突 | 需人工复核（缺：对应正式规则或证据） |
| 用户要求保证满分 | 改为满分覆盖矩阵，不承诺实际满分 |
| 关键词与工程对象不匹配 | 删除或降级为风险提示，禁止硬塞行业词 |
| 参数、检测频次、验收结论无正式依据 | 标待确认或改为“拟按招标、图纸、规范和审批方案执行” |
| 新项目资料包已上传但未生成项目级关键词覆盖矩阵 | 先执行关键词动态增强规则，再生成评分响应矩阵或施组正文 |

## 4 关键词权重规则

| 出现位置 | 识别权重 | 嵌入规则 | 判断逻辑 |
|---|---:|---|---|
| 章节标题 | 高 | 标题含评分关键词、工程对象或关键工序，例如“质量保证与隐蔽验收控制措施” | AI 优先判断该章是否响应评分项 |
| 节点名称 | 高 | 节点名含“问题—措施—参数—验收—证据”中的对象词或动作词 | 便于抽取工序节点和控制节点 |
| 评分点/评分响应矩阵 | 高 | 评分项原文、满分关键词、AI识别词、证据列同时出现 | 作为满分覆盖和缺口判断核心依据 |
| 证据留痕字段 | 高 | 出现旁站记录、检测报告、隐蔽验收、影像资料、整改复查、归档清单 | 强化可追溯性、可信度和专家判断权重 |
| 工艺流程 | 中高 | 工序顺序与工程对象绑定，如测量复核、沟槽开挖、管道安装、闭水通水 | 判断方案是否可实施、是否覆盖主要施工内容 |

| 控制措施 | 中 | 说明责任主体、资源配置、施工方法和动态纠偏 | 判断针对性和组织能力 |

| 输出模板示例 | 中 | 模板中嵌入评分关键词、工艺关键词、验收关键词和证据词 | 引导生成稳定命中表达 |

### 4.1 关键词分布密度规则

1. 每个评分项至少在标题、段首、正文工序、检查验收、资料留痕和评标映射中各出现一次核心词或同义词。
2. 同一段落不连续堆砌同类词；采用“关键词 + 工程对象 + 控制动作 + 验收证据”的自然句。
3. 高频词优先放在标题、表头、段首和证据列；普通说明中降低重复，避免机械罗列。
4. 同义词用于分散表达：质量保证/质量控制/检验检测，安全文明/风险分级/隐患整改，绿色施工/环保控制/低碳台账。
5. 缺项目资料时，关键词可作为候选表达，但必须同时出现“拟、计划、待确认、需补充、经审批实施”等证据边界词。

## 5 关键词动态增强规则（Project Keyword Dynamic Enhancement Rule）

当系统每次录入新的项目资料包时，不得只调用通用行业知识，必须自动读取该项目的招标文件、答疑澄清、补遗变更、工程量清单、图纸、设计说明、勘察资料、现场踏勘资料、技术标准和评标办法，动态生成“项目级关键词覆盖矩阵”。该矩阵用于后续施工组织设计自动编制、内容审查、AI 评标匹配和得分优化。

### 5.1 触发条件

任一新项目创建或上传下列资料时自动触发：

1. 招标文件。
2. 答疑、澄清、补遗、变更文件。
3. 工程量清单。
4. 图纸、设计说明、勘察资料。
5. 现场踏勘图片、踏勘记录。
6. 技术标准和要求。
7. 评标办法或评分标准。

### 5.3 项目级关键词权重规则

| 来源或词类 | 权重等级 | 规则 |
|---|---|---|
| 答疑澄清、补遗变更中出现的关键词 | 最高权重 | 覆盖原招标文件旧关键词，禁止继续引用被澄清替代的旧内容 |
| 评分标准中的评分项和扣分项 | 最高权重 | 必须进入评分响应矩阵和对应正文章节 |
| 招标范围和工程量清单中的主要工程对象 | 高权重 | 主要清单子目必须进入工程对象关键词 |
| 图纸中的结构参数、材料规格、断面尺寸、施工范围 | 高权重 | 必须进入材料参数、工艺控制或质量验收 |
| 技术标准和合同条款中的强制性要求 | 高权重 | 作为合规、验收和风险控制依据 |
| 现场踏勘资料中的施工条件、风险点、交通条件、周边环境 | 中高权重 | 进入施工部署、总平、重难点、安全环保和风险闭环 |
| 通用质量、安全、进度、环保管理词 | 普通权重 | 仅作为章节支撑，不得替代项目级关键词 |
| 空泛口号类词语 | 低权重或剔除 | “高度重视、科学组织、确保顺利、加强管理”等不得提升为高权重 |

### 5.5 施组编制调用规则

后续自动编制施工组织设计时，必须先调用项目级关键词覆盖矩阵，再生成评分响应矩阵、章节目录和正文草案：

1. 每个评分章节必须覆盖对应评分关键词。
2. 每个主要工程对象必须至少出现在工程概况、重点难点、施工方案、质量控制、安全控制、进度组织或总平面布置中。
3. 关键施工工艺必须写成“工序流程+操作措施+质量控制+验收标准+留痕资料”。
4. 风险关键词必须写成“风险识别+应对措施+检查频次+责任人+留痕资料”。
5. 材料和参数关键词必须写入材料控制、工艺控制或质量验收内容。
6. 答疑澄清关键词必须优先覆盖，禁止继续引用被澄清替代的旧内容。
7. 不得机械堆砌关键词，应将关键词自然嵌入施工措施、技术参数、检查动作和验收标准中。
8. 对青天大模型 AI 类人评标重点关注内容，应强化项目对应性、评分项覆盖、参数化表达、工艺闭环、质量安全环保留痕。

### 5.6 AI 评标优化目标

| 目标 | 验证方式 |
|---|---|
| 评分项全覆盖 | 评分标准与评分响应矩阵逐项映射 |

### 5.7 调试与验收接口约束

项目级关键词动态增强能力必须提供只读调试输出或本地测试输出，可检查触发资料、提取关键词、权重等级、来源页码或条款、答疑覆盖关系、正文调用位置和空泛词剔除结果。调试输出不得包含真实密钥、Token、Cookie、Authorization、AppSecret、SSH key、数据库文件、日志文件或缓存文件。

## 12 高分理由生成规则

每个评分项至少形成四类理由：

1. 完整性理由：覆盖评分要求、工程对象、关键工序、资源保障、验收标准、证据留痕和风险闭环。
2. 针对性理由：对应本项目部位、现场条件、工况节点、接口边界、重难点和资料状态。
3. 可实施性理由：有责任主体、岗位班组、机械材料、检查频次、控制目标、验收方法和成果文件。
4. 可追溯性理由：有招标证据、图纸清单、旁站记录、检测报告、隐蔽验收、整改复核、影像资料或归档清单。

推荐句式：本节围绕【评分项】设置【措施类别】，针对【项目难点】提出【具体方法】，并通过【资源配置/过程检查/验收记录/整改闭环/证据留痕】形成可实施、可检查、可追溯的控制链，可满足招标文件关于【质量/工期/安全/环保/绿色施工/智慧建造】的要求，具备支撑高分评价的充分理由。

禁写：高度重视、严格落实、确保万无一失、充分发挥优势、经验丰富、按规范执行但无具体措施、保证满分、自动推荐、法定通过。

## 13 初步评审与暗标避险

| 风险 | 审查动作 |
|---|---|
| 工期、质量、安全、缺陷责任期与招标不一致 | 与招标文件逐项比对，评分响应矩阵中保留证据来源 |
| 项目名称、标段、地点、招标人、建设内容错误 | 输出前统一核对，缺资料标需补充 |
| 其他项目残留、雷同同错 | 搜索地名、单位名、项目名、重复段、行业不符工序 |
| 暗标身份泄露 | 删除投标人名称、简称、Logo、人员姓名、证书编号、联系方式、荣誉业绩、专属系统名 |
| 格式、页数、字体、目录、图表不合规 | 缺规则时输出需人工复核 |
| 把计划写成已完成 | 改为拟采用、计划配置、中标后经审批实施、形成记录作为验收依据 |
| 异常低价禁用理由 | 不得写亏本让利、人员闲置、机械闲置、材料自有、类似业绩摊薄 |
| 关键词堆砌或行业错配 | 调整为工程对象、工序、验收、证据自然嵌入；无关词删除 |

## 15 评分预测模型

仅用于找缺口，不得伪造评标结果。

| score_item | max_score | response_sections | keyword_density | keyword_weight_location | evidence_density | project_specificity | constructability | acceptance_closure | evidence_traceability | compliance_risk | dark_bid_risk | similarity_risk | expected_score_band | repair_action |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|

expected_score_band 只写“高/中/低风险区间”或“待评分标准确认”，不得写确定得分。

keyword_weight_location 按“标题/评分点/工艺流程/验收标准/证据留痕/普通描述”归类；仅普通描述命中不得判断为高覆盖。

## 16 关系链

```text
KG02 --requires--> KG01。评分矩阵必须绑定工程对象和证据边界。
KG02 --uses--> KG03。跨行业能力进入评分前必须审计。
KG02 --drives--> KG04。最终施组按矩阵、模板和审校器生成。

答疑澄清/补遗变更 --overrides--> 原招标文件旧关键词。
关键词增强层 --maps_to--> 评分项、工程对象、工序节点、验收标准、证据留痕。

工序节点 --expressed_as--> 问题—措施—参数—验收—证据。

```
