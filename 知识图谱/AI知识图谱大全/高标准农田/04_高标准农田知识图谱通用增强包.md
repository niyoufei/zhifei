# 04_高标准农田知识图谱通用增强包

## 文件用途

本文件按《通用型知识图谱增强指令》对现有高标准农田知识图谱进行系统性增强。它用于补齐通用节点体系、关系边、评分项词库、规则占位节点、四步闭环、语言护栏、冲突处理和导出字段, 使图谱进一步具备可检索、可推理、可评分、可审查、可导出、可持续升级能力。

本文件可上传 GPT Knowledge, 优先级低于 `01_高标准农田工程知识图谱.md`、`02_高标准农田接口与专项工程知识图谱.md`、`03_高标准农田青天AI评标门控.md`, 高于原增强版写作素材。

## 证据等级统一规则

增强后的图谱统一使用以下三段证据等级。既有文件中的旧证据等级保留, 但在检索、审查和导出时按本表转换。

| 增强证据等级 | 含义 | 可支撑表达 | 旧等级映射 |
|---|---|---|---|
| A_primary | 招标文件、答疑、合同、图纸、清单、评分办法、正式规范、平台正式规则、用户指定准绳 | 强制规则、审查依据、扣分判断、项目事实 | A_primary; A_governance 中有正式来源者; B_primary_composite 中来源齐全者 |
| A_secondary | 行业经验、常见评分项、常见施工措施、专家经验词库、通用写作模板 | 增强召回、补充写作、常见风险提示 | C_rule_composite; 原增强版 00-04; 评分项词库 |
| A_pending | 待上传正式文件、待确认地方规则、待确认暗标规则、待确认 AI 评标规则、缺参缺证 | 只能提示需补充、需人工复核和关闭动作 | D_open_issue; open_issue=True 且缺正式 source 的节点 |

### 证据升级规则

| 当前状态 | 升级条件 | 升级后等级 | 禁止事项 |
|---|---|---|---|
| A_secondary 常见评分项 | 补充招标文件评分项原文、分值、页码或条款 | A_primary | 不得先写成评分项原文 |
| A_pending 暗标规则 | 补充招标文件暗标条款或平台规则 | A_primary | 不得虚构字体、页眉页脚、身份线索规则 |
| A_pending 工程参数 | 补充图纸、清单、设计说明、设备表或记录 | A_primary | 不得用经验值替代 |
| A_secondary 施工措施 | 经项目施工方案、技术交底或监理审批确认 | A_primary | 不得写成已批准或已实施 |
| A_pending 验收交付 | 补充四方验收、试用、竣工图、移交、管护协议 | A_primary | 不得写已验收、已移交 |

## 第六部分：语言护栏增强

### 禁用词库与替换原则

| 禁用或限制表达 | 问题 | 推荐替换方向 |
|---|---|---|
| 加强管理 | 无主体、无动作 | 由【岗位】对【对象】按【频次】检查并形成【记录】 |
| 高度重视 | 空泛态度 | 将【评分项】分解为【工程对象】和【控制点】 |
| 确保质量 | 无验证方式 | 对【工序】执行【标准】并形成【检测/验收资料】 |
| 严格落实 | 无执行链 | 按【流程】实施, 由【责任人】复核 |
| 做好保障 | 无资源 | 配置【人员/机械/材料/检测资源】 |
| 完善措施 | 无措施内容 | 设置【措施名称、适用对象、检查方式】 |
| 提高效率 | 无量化 | 通过【流水组织/资源调配】缩短【节点等待时间】 |
| 有序推进 | 无进度控制 | 按【关键节点】推进并执行【纠偏机制】 |
| 认真执行 | 无责任 | 由【岗位】执行【动作】并归档【记录】 |

### AI 评标友好表达规则

1. 标题含评分项关键词。
2. 首句直接回应评分项。
3. 每段只解决一个评分点或一个工程对象。
4. 每项措施包含对象、动作、责任、频次、标准、记录。
5. 缺参数时写 `需补充（缺：××）`。
6. 风险和整改必须能回到节点、证据或 closure_action。
7. 不写身份线索、业绩线索、完成态越权表达。

### 青天 AI 关键词权重与嵌入规则

| 关键词位置 | 权重等级 | 必须嵌入的字段 | 可识别表达 |
|---|---|---|---|
| 标题和节点名称 | high | 评分项原文、工程对象、控制目标 | “田块整治关键工序与质量控制” |
| 评分点和评标映射 | high | 满分关键词、分值、响应章节、扣分风险 | “评分项-工程对象-措施-证据”同表出现 |
| 证据留痕 | high | 旁站记录、检测报告、隐蔽验收、影像资料、整改复核 | “对象编号 + 记录名称 + 验收结论 + 归档位置” |
| 工艺流程和控制措施 | medium_high | 关键工序、参数标准、检查频次、责任主体 | “先测量复核, 再工序实施, 后验收准出” |
| 验收标准和质量安全绿色检查 | medium_high | 验收方法、质量标准、安全风险、绿色施工 | “检查频次 + 不合格处置 + 整改闭环” |
| 风险应对和动态优化 | medium | 风险触发、blocker、closure_action、复核状态 | “风险识别-处置措施-整改复核” |
| 普通描述 | low | 背景、概念、通用原则 | 只能辅助召回, 不单独支撑得分 |

### 项目级关键词动态增强规则

| 规则项 | 要求 |
|---|---|
| 规则名称 | 关键词动态增强规则（Project Keyword Dynamic Enhancement Rule） |
| 触发条件 | 新项目创建或上传招标文件、答疑澄清、补遗变更、工程量清单、图纸设计说明、踏勘资料、技术标准、评标办法任一资料 |
| 输出产物 | project_keyword_coverage_matrix |
| 覆盖类别 | 项目基础、评分、工程对象、施工工艺、材料参数、风险控制、验收检测、答疑澄清覆盖 |
| 最高权重 | 答疑澄清/补遗变更关键词、评分标准评分项和扣分项 |
| 高权重 | 招标范围、清单主要工程对象、图纸结构参数、技术标准强制要求 |
| 中高权重 | 现场踏勘施工条件、风险点、交通条件、周边环境 |
| 低权重或剔除 | 高度重视、科学组织、确保顺利、加强管理等空泛口号 |
| 准入门控 | 未生成矩阵不得进入完整施组自动编制、AI 评标匹配和得分优化 |
| 审计要求 | 每个关键词均需来源文件、页码或条款号、对应工程部位、对应章节和留痕资料 |
