# 高标准农田常见评分项词库与响应路由

## 文件用途

本文件用于补充高标准农田技术标和施工组织设计中的常见评分项关键词、工程对象路由、写作块调用、证据要求和扣分风险。它可上传 GPT Knowledge, 用于增强评分项识别和章节生成稳定性。

本文件不替代招标文件评分标准。评分项原文、分值、等级、否决项和暗标格式要求必须以具体招标文件为准。

## 使用边界

1. 词库只用于识别和路由, 不证明具体项目评分项存在。
2. 未提供招标文件时, 不得把本文件中的评分项写成“评分项原文”。
3. 每个评分项仍需绑定项目证据、工程对象、施工措施、资源保障、验收闭环和 blocker。
4. 缺图纸、清单、参数、验收记录时必须写 `需补充`。

## 关键词嵌入位置与权重提示

| 嵌入位置 | 推荐写法 | 权重 | 常见问题 | 修正方向 |
|---|---|---:|---|---|
| 章节标题 | “评分项原文/近义词 + 工程对象 + 控制目标” | 高 | 标题只写管理口号 | 改为“田块整治关键工序与质量控制” |
| 节点名称 | “工程对象 + 专项控制/验收准出/证据留痕” | 高 | 节点名过泛 | 加入田块、灌排、路桥、电气、防护、管护对象 |

| 控制措施 | “责任主体 + 动作 + 频次 + 记录” | 中高 | 无主体无频次 | 补岗位、巡查频次、整改复核 |
| 参数标准 | “以图纸/清单/检测为准, 缺项需补充” | 中高 | 经验估算参数 | 写待补证据和阻断表达 |

| 输出模板示例 | “问题-措施-参数-验收-证据” | 高 | 关键词堆砌 | 一段只响应一个评分点 |

## 高分响应模板库

### 模板 1: 施工组织设计科学合理

```text
本节针对“【评分项原文】”要求进行响应。结合本项目【工程对象】和【证据来源】，项目部拟按“分区分片、关键工序、接口闭合、资料同步”的原则组织施工，将田块整治、地力提升、灌排输配电、田间道路、防护生态和建后管护纳入统一计划，明确【控制目标】、【检查频次】和【责任主体】，配置【资源】并形成【旁站记录/检测报告/隐蔽验收/影像资料/验收移交资料】。对【缺证项】设置【blocker、整改复核与关闭动作】，确保施工组织具备完整性、针对性、可实施性和可追溯性。
```

## 输出检查规则

生成任何评分响应时, 必须检查:

1. 是否使用评分项原文或近似关键词做标题。
2. 是否绑定至少一个高标准农田工程对象。
3. 是否包含措施、资源、标准、记录或验收闭环。
4. 是否标明缺证参数和修正动作。
5. 是否避免完成态越权、暗标身份线索和异常低价禁止理由。
