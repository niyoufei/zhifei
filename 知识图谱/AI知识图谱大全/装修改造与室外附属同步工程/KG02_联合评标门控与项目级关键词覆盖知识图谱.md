## 1 青天 AI 类人评标抽象链

```text
招标评分项解析 -> 联合范围判定 -> 投标文件响应抽取 -> 章节/表格/锚点定位 -> 完整性/针对性/可实施性判断 -> 接口闭合和穿插风险判断 -> 高分理由生成 -> 风险扣分识别 -> 人工复核或评分建议
```

施工组织设计必须让 AI 稳定判断：评分项是否被明确响应、响应在哪里、是否贴合本项目、DECO/EXT/JOINT 范围是否有证据、室内外接口是否清楚、措施是否具体可执行、记录是否能支撑高分、是否存在漏项、矛盾、暗标、雷同、越权或完成态无证据。

## 2 Fail-Fast 门控

| 场景 | 必须输出 |
|---|---|
| 缺招标文件或技术文件评分标准 | 需补充（缺：招标文件和技术文件评分标准） |
| 缺图纸、清单、工程范围或专业边界 | 需补充（缺：项目范围/图纸/清单/专业边界） |
| 缺装修改造或室外附属任一专业资料 | 不启用 JOINT，同步施工只作为待确认风险 |
| 缺室内外界面划分、总平、竖向、管综、接驳条件 | 需补充（缺：室内外接口资料） |
| 缺暗标规则、格式、页数、签章上传规则 | 需人工复核（缺：暗标/格式/平台规则） |
| 涉及法定责任、异常低价、自动否决、雷达异常、证据冲突 | 需人工复核（缺：对应正式规则或证据） |
| 用户要求保证满分 | 改为满分覆盖矩阵，不承诺实际满分 |
| 关键词与工程对象不匹配 | 删除或降级为风险提示，禁止硬塞行业词 |
| 参数、检测频次、验收结论无正式依据 | 标待确认或改为“拟按招标、图纸、规范和审批方案执行” |
| 新项目资料包已上传但未生成联合项目级关键词覆盖矩阵 | 先执行关键词动态增强规则，再生成评分响应矩阵或施组正文 |

## 3 联合项目级关键词动态增强规则

新项目创建或上传任一项目资料时，系统必须先生成“联合项目级关键词覆盖矩阵”，不得只调用通用行业知识。该矩阵作为施工组织设计自动编制、内容审查、AI 评标匹配和得分优化的 A_project_keyword 前置输入。

| 规则项 | 强制要求 |
|---|---|
| 触发条件 | 上传招标文件、答疑澄清、补遗变更、工程量清单、图纸、设计说明、勘察资料、踏勘图片/记录、技术标准和要求、评标办法或评分标准时自动触发 |
| 资料读取 | 逐项读取项目名称、标段、项目编号、建设地点、招标人、工期、质量目标、项目类别、标段划分、招标范围、清单子目、图纸参数、技术标准、踏勘风险、室内外接口 |
| 关键词分类 | 项目基础关键词、评分关键词、DECO 工程对象关键词、EXT 工程对象关键词、JOINT 接口关键词、穿插施工关键词、材料与参数关键词、风险控制关键词、验收检测关键词、答疑澄清覆盖关键词、空泛低权重词 |
| 工程对象细化 | 从招标范围、清单和图纸抽取具体对象，不得只写上位泛称；室内对象、室外对象和接口对象必须分别标记 |
| 答疑覆盖 | 答疑、澄清、补遗、变更优先级高于原招标文件；凡修改评分标准、清单子目、工期、资格、材料、技术参数、接口边界或报价要求的，覆盖旧关键词并标记“高优先级关键词” |
| 输出结构 | 关键词、关键词类别、domain_tag、interface_tag、来源文件、来源页码或条款号、对应工程部位、对应施组章节、推荐写入方式、权重等级、风险等级、是否评分关键词、是否答疑澄清覆盖关键词、是否必须在技术标正文中出现、建议出现频次、可关联检测/验收/留痕资料 |
| 编制调用 | 后续施组必须调用联合项目级关键词覆盖矩阵；每个评分章节覆盖评分关键词，每个主要 DECO/EXT 对象至少进入工程概况、重难点、施工方案、质量控制、安全控制、进度组织或总平面布置，JOINT 对象必须进入接口、穿插或联合验收章节 |
| 表达要求 | 关键工艺写成“工序流程 + 操作措施 + 质量控制 + 验收标准 + 留痕资料”；同步施工写成“室内作业 + 室外作业 + 冲突点 + 前置条件 + 保护措施 + 检查记录 + 纠偏动作” |
| 禁止事项 | 不得机械堆砌关键词；禁止继续引用被答疑澄清替代的旧内容；不得把空泛口号提升为高权重；不得引入项目资料未出现且不属于本项目范围的工程对象 |

## 4 关键词权重规则

| 出现位置 | 权重等级 | 判断逻辑 | 写入要求 |
|---|---:|---|---|
| 章节标题/小节标题 | 高 | 标题最易被 AI 用作章节锚点和评分项召回 | 标题保留评分项原词、工程对象或接口关键词 |
| 节点名称/评分项名称 | 高 | 节点名直接建立 Knowledge 节点与评分项映射 | 节点名称包含 DECO/EXT/JOINT 对象、关键工序或控制目标 |
| 评分点原文/最高档拆解 | 高 | 评分项原文是类人评标主证据 | 不得改写原文；补完整性、针对性、可实施性、验收闭环 |
| 证据留痕/资料矩阵 | 高 | 可反查记录提高专业判断权重 | 绑定旁站记录、检测报告、隐蔽验收、影像资料、整改复核、签认台账 |
| 室内外接口责任矩阵 | 高 | 判断同步项目是否真的有界面闭合 | 每个 JOINT 对象必须有责任边界、前置条件和移交资料 |
| 穿插施工计划矩阵 | 中高 | 判断进度组织是否贴合现场 | 写清室内外作业、冲突点、保护措施和纠偏动作 |
| 工艺流程/关键工序说明 | 中高 | 判断措施是否可执行 | 用“工序节点 + 责任主体 + 动作 + 频次/标准”表达 |
| 验收标准/检查方法 | 中高 | 判断质量标准和闭环是否完整 | 写明检查频次、验收方法和资料依据；无来源参数标 A_pending |
| 普通叙述性描述 | 低 | 只提供辅助语义，不能独立支撑高分 | 避免只写管理口号；必须向工序、验收或证据回链 |
| 无关行业堆砌 | 禁用 | 与项目资料不匹配 | 删除、降级或标为行业不匹配 |

## 5 联合评分响应矩阵 Schema

| 字段 | 规则 |
|---|---|
| 评分项原文 | 不得随意改写，优先复制招标文件原文；标题、段首和矩阵行应保留评分关键词 |
| 分值/等级 | 来自评分办法，缺失不得自行估分 |
| 满分关键词 | 提取评分标准中的高价值词；缺失时用通用词库候选并标待确认 |
| domain_tag | DECO、EXT、JOINT 或组合；必须来自项目资料命中 |
| interface_tag | 无接口、室内外界面、消防内外网、给排水接驳、电气弱电接入、出入口高差、临设总平、联合验收等 |
| 招标证据 | 招标文件、答疑、图纸、清单、规范、平台规则 |
| 工程对象 | 装修改造对象、室外附属对象、联合接口对象 |
| 响应章节 | 章节标题应包含评分关键词、工程对象或接口节点；避免标题泛化为“相关措施” |
| 四步闭环 | 目标任务、风险难点、执行措施、验证检查；正文优先扩展为“问题 - 措施 - 参数 - 验收 - 证据” |
| 穿插关系 | 前后置关系、同步窗口、冲突点、保护措施、检查记录 |
| 资源保障 | 人员、机械、材料、检测、临设、交通、清运、管理职责、替补机制 |
| 验收闭环 | 检查、检测、隐蔽验收、联合调试、整改、复核、归档、移交 |
| blocker/扣分风险 | 缺证、缺图、暗标、越权、接口不清、参数无依据、行业错配、完成态越权 |
| 修正动作 | 补资料、降级表达、改写标题、增加表格、补证据留痕、人工复核 |

## 9 输出等级

| 等级 | 条件 | 允许结论 |
|---|---|---|
| 满分候选稿 | 评分项全覆盖、JOINT-FULL 全通过、五锚点齐全、关键词权重命中、联合项目级矩阵已调用、无未关闭 blocker | 具备满分候选条件 |
| 满分候选需补证稿 | 主要内容覆盖，但存在 A_pending 参数、格式、接口或专项证据 | 满分候选需补证 |
| 高分候选稿 | 评分响应基本完整，但部分接口、参数或验收资料需补充 | 具备高分候选条件，列明缺口 |
| 尚不具备 | 缺评分办法、暗标规则、范围资料或存在否决/接口重大风险 | 尚不具备满分候选条件 |

## 10 关系链

```text
JOINT-MAX-002 --produces--> JOINT-FULL-03。评分项原文生成最高档语义拆解。
JOINT-MAX-003 --produces--> JOINT-FULL-02。联合范围判定决定是否启用 JOINT。
JOINT-MAX-005 --requires--> JOINT-OBJ-*。满分响应单元必须绑定工程对象。
JOINT-MAX-006 --produces--> JOINT-FULL-06。五锚点用于青天 AI 抽取定位。
JOINT-MAX-007 --checked_by--> JOINT-FULL-09。接口责任必须闭合。
JOINT-MAX-008 --checked_by--> JOINT-FULL-10。穿插计划必须无矛盾。
```
