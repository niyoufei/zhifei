## 1 最终生成协议

输出最终施组或优化稿时，必须按以下顺序：

1. 满分覆盖边界：说明本稿用于提高评分覆盖度，不承诺实际满分。
2. 项目资料矩阵：登记招标、答疑、清单、图纸、评分、暗标、接口资料和证据等级。
3. 联合范围判定表：说明 DECO、EXT、JOINT 是否被 A_primary 资料触发。
4. 联合项目级关键词覆盖矩阵：从招标、答疑澄清、补遗变更、清单、图纸、技术标准和踏勘资料提取关键词、来源、权重和正文调用位置。
5. 评分响应矩阵：逐条列评分项、关键词、domain_tag、对象、章节、证据、措施、记录、blocker、整改动作。
6. 室内外接口责任矩阵：列接口对象、装修侧节点、室外侧节点、责任边界、配合动作、移交标准和会签资料。
7. 穿插施工计划矩阵：列阶段、室内作业、室外作业、冲突点、前置条件、保护措施、检查记录和纠偏动作。
8. 联合验收移交矩阵：列系统/部位、装修验收资料、室外验收资料、联合调试资料、移交条件和 A_pending 缺口。
9. 章节目录：按评分项、项目级关键词、DECO/EXT 工程对象和 JOINT 接口组织。
10. 正文草案：每章采用问题 - 措施 - 参数 - 验收 - 证据闭环并自然嵌入项目级关键词。
11. 专项表格：资源、进度、质量、安全、环保、接口、项目关键词调用、V9 调用审计。
12. 反向审校：列扣分风险、触发位置、修改动作、复检标准。
13. 待补资料与人工复核项。

不得只输出正文。

## 4 联合矩阵调用规则

| 调用对象 | 正文嵌入规则 | 审校标准 |
|---|---|---|
| 评分关键词 | 每个评分章节标题、段首或矩阵行必须出现对应评分关键词 | 评分项全覆盖，无漏项 |
| DECO 工程对象关键词 | 室内主要清单子目和图纸部位进入工程概况、重难点、施工方案、质量、安全、进度 | 室内对象不泛化，名称与清单/图纸一致 |
| EXT 工程对象关键词 | 室外主要清单子目和图纸部位进入工程概况、重难点、施工方案、质量、安全、进度或总平 | 室外对象不泛化，名称与清单/图纸一致 |
| JOINT 接口关键词 | 出入口、排水、消防、电气弱电、临设、物流、成品保护、联合验收进入接口章节和表格 | 接口有责任边界、前置条件和移交资料 |
| 施工工艺关键词 | 写成“工序流程 + 操作措施 + 质量控制 + 验收标准 + 留痕资料” | 工艺闭环完整，避免只写管理口号 |
| 穿插施工关键词 | 写成“室内作业 + 室外作业 + 冲突点 + 前置条件 + 保护措施 + 检查记录 + 纠偏动作” | 穿插关系无矛盾，前置条件清楚 |
| 材料与参数关键词 | 写入材料控制、工艺控制或质量验收，并注明来源文件、页码或条款 | 参数可追溯，无依据参数标待确认 |
| 风险控制关键词 | 写成“风险识别 + 应对措施 + 检查频次 + 责任人 + 留痕资料” | 风险对应现场条件，整改复核闭合 |
| 验收检测关键词 | 关联检测报告、见证取样、隐蔽验收、工序验收、联合调试、影像资料和资料归档 | 每项关键措施有验收标准和证据留痕 |
| 答疑澄清覆盖关键词 | 优先采用答疑澄清、补遗变更后的新关键词 | 禁止继续引用被替代旧内容 |
