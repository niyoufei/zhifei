## 项目级关键词覆盖矩阵导出契约

项目资料包触发关键词动态增强后，必须导出结构化矩阵，供施组生成、内容审查、青天 AI 评标匹配和得分优化复用。

| 字段 | 含义 | 证据要求 |
|---|---|---|
| keyword | 从项目资料抽取的原文关键词或参数表达 | 不得改写导致与原文不一致 |
| keyword_category | 项目基础、评分、工程对象、施工工艺、材料参数、风险控制、验收检测、答疑覆盖、低权重清洗 | 分类必须与来源语境一致 |
| source_file | 来源文件名称 | 招标、答疑、清单、图纸、技术标准、踏勘资料等 |
| source_locator | 来源页码、条款号、图号或行号 | 缺页码时至少保留可回溯行号/段落 |
| project_part | 对应工程部位、清单子目、评分章节或风险场景 | 不得泛化为无对象描述 |
| suggested_section | 推荐写入的施组章节 | 必须覆盖工程概况、重点难点、施工方案、质量、安全、环保、进度、验收等对应章节 |
| write_method | 推荐写入方式 | 按问题—措施—参数—验收—证据或风险闭环表达 |
| weight_level | 最高、高、中高、普通、低 | 答疑覆盖和评分项最高；清单对象、图纸参数、强制标准高；空话低 |
| risk_level | 高、中高、中、低 | 反映扣分、质量、安全、环保、接口和进度风险 |
| is_scoring_keyword | 是否评分关键词 | 评分项、扣分项、最高档、页数限制、AI 辅助评审要求为 true |
| is_clarification_override | 是否答疑澄清覆盖关键词 | 覆盖旧工期、评分、清单、材料、参数或报价要求时为 true |
| must_appear_in_technical_bid | 是否必须进入技术标正文 | 最高/高/中高权重且非低权重清洗词为 true |
| suggested_frequency | 建议出现频次 | 高频但不生硬，优先分布在标题、段首、工艺、验收、证据字段 |
| linked_evidence | 可关联检测、验收、留痕资料 | 检测报告、隐蔽验收、见证取样、旁站记录、影像留痕、资料归档等 |

## 持续升级规则

1. 新增节点必须有证据等级、适用条件、风险、验证点和映射章节。
2. A_secondary 节点不得写成强制规则；A_pending 节点必须有补证动作。
3. 关系边必须说明方向、触发条件和冲突规则。
4. 评分词库要同时补关键词和同义词，服务 RAG 检索和青天 AI 抽取。
5. 关键词必须分布在标题、评分点、工艺流程、验收标准和证据留痕等高/中高权重位置；仅在普通描述中出现不得作为高分依据。
6. 每次新项目资料包录入后必须生成项目级关键词覆盖矩阵，并记录来源文件、页码/条款、权重、是否答疑覆盖和建议写入章节。
7. 图谱升级后必须更新 Knowledge 调用审计表，说明新增内容进入哪个上传文件、写入章节、权重位置和证据状态。
