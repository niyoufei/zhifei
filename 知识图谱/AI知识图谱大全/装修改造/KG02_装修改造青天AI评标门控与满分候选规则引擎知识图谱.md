# KG02 装修改造青天AI评标门控与满分候选规则引擎知识图谱

## 文件用途

本文件为 ChatGPT 自定义 GPT 上传用 Knowledge 之二，服务安徽青天 AI 类人评标场景下装修改造施工组织设计的评分项解析、初步评审避险、暗标雷同清洗、AI 可抽取锚点、高分理由反查和满分候选释放。它不替代评标委员会、招标文件、监管规则或平台正式结论。

## 评标硬边界

1. 缺招标文件、评分办法、评分标准、暗标规则、格式要求时，不得生成确定分值、满分关键词或满分候选结论。
2. 技术评分必须绑定评分项原文、工程对象、施工措施、资源保障、验收闭环和证据来源。
3. 暗标技术文件不得出现单位名、简称、Logo、人员姓名、证书、联系方式、荣誉、业绩、专属系统、作者属性、文件路径、项目残留。
4. 异常低价解释不得使用亏本让利、人员闲置、机械闲置、材料自有、类似业绩降本等高风险理由。
5. 自动推荐、自动否决、无人化评标结论必须有招标文件、监管平台或试点规则明确授权；缺授权时只输出需人工复核。
6. V9 和行业经验不得作为否决、自动推荐或最终满分判断依据，只能作为 A_secondary 写作增强。

## 青天 AI 类人评审抽象链

```text
招标评分项解析 -> 投标文件响应抽取 -> 章节/表格/锚点定位 -> 完整性/针对性/可实施性判断 -> 高分理由生成 -> 风险扣分识别 -> 人工复核或评分建议
```

施工组织设计必须让 AI 稳定判断：评分项是否被明确响应、响应在哪里、是否贴合本项目、措施是否具体可执行、记录是否能支撑高分、是否存在漏项/矛盾/暗标/雷同/越权。

## 青天 AI 可识别关键词权重规则

关键词权重用于判定“是否高相关、是否可评分、是否可反查”。同一评分项应至少在标题、段首响应、工艺措施、验收标准、证据留痕中形成三处以上有效命中，避免只在普通描述中低权重出现。

| 关键词出现位置 | 权重等级 | 建议权重 | 青天识别逻辑 | 写入要求 |
|---|---|---:|---|---|
| 章节标题/小节标题 | 高权重 | 1.00 | 标题最易被 AI 用作章节锚点和评分项召回 | 标题保留评分项原词或同义词，如“质量保证措施：样板引路、隐蔽验收与整改复核” |
| 节点名称/评分项名称 | 高权重 | 0.98 | 节点名直接建立 Knowledge 节点与评分项映射 | 节点名称包含工程对象、关键工序或控制目标 |
| 评分点原文/最高档拆解 | 高权重 | 0.95 | 评分项原文是类人评标的主证据 | 不得改写原文；在拆解字段中补完整性、针对性、可实施性、验收闭环 |
| 证据留痕/资料矩阵 | 高权重 | 0.95 | 可反查记录提高专业判断权重 | 绑定旁站记录、检测报告、隐蔽验收、影像资料、整改复核、签认台账 |
| 工艺流程/关键工序说明 | 中高权重 | 0.85 | 判断措施是否可执行和贴合装修改造场景 | 用“工序节点+责任主体+动作+频次/标准”表达 |
| 验收标准/检查方法 | 中高权重 | 0.85 | 判断质量标准、验收方法和闭环是否完整 | 写明检查频次、验收方法、允许偏差或资料依据；无来源参数标 A_pending |
| 控制措施/风险应对 | 中权重 | 0.75 | 判断风险识别和整改闭环 | 按“风险点—预控措施—整改复核—销项证据”表达 |
| 参数标准/资源配置 | 中权重 | 0.70 | 判断可实施性和资源匹配 | 参数必须有图纸、清单、规范、设备说明或待补标识 |
| 普通叙述性描述 | 低权重 | 0.35 | 只提供辅助语义，不能独立支撑高分 | 避免只写管理口号；必须向工序、验收或证据回链 |
| 同义词/近义词命中 | 辅助权重 | 0.60 | 提升召回但不能替代评分原词 | 同义词与原词并列出现，如“复验/复检/整改复核”“管综/综合排布” |

## 关键词动态增强规则（Project Keyword Dynamic Enhancement Rule）

新项目创建或上传任一项目资料时，系统必须先生成“项目级关键词覆盖矩阵”，不得只调用通用行业知识。项目级矩阵作为施工组织设计自动编制、内容审查、AI 评标匹配和得分优化的 A_primary/A_pending 前置输入。

| 规则项 | 强制要求 |
|---|---|
| 触发条件 | 上传招标文件、答疑澄清、补遗变更、工程量清单、图纸、设计说明、勘察资料、踏勘图片/记录、技术标准和要求、评标办法或评分标准时自动触发 |
| 资料读取 | 逐项读取项目名称、标段、项目编号、建设地点、招标人、工期、质量目标、合同估算价、最高投标限价、项目类别、标段划分、招标范围、清单子目、图纸参数、技术标准、踏勘风险 |
| 关键词分类 | 项目基础关键词、评分关键词、工程对象关键词、施工工艺关键词、材料与参数关键词、风险控制关键词、验收检测关键词、答疑澄清覆盖关键词、空泛低权重词 |
| 工程对象细化 | 从招标范围、清单和图纸抽取具体工程对象，不得只写上位泛称；如项目资料出现“金属网兜抛石护岸、格网石笼、堤后盖重压渗平台、双轮铣防渗墙”等，必须按原文进入项目级矩阵 |
| 答疑覆盖 | 答疑、澄清、补遗、变更优先级高于原招标文件；凡修改评分标准、清单子目、工期、资格、材料、技术参数或报价要求的，覆盖旧关键词并标记“高优先级关键词” |
| 输出结构 | 关键词、关键词类别、来源文件、来源页码或条款号、对应工程部位、对应施组章节、推荐写入方式、权重等级、风险等级、是否评分关键词、是否答疑澄清覆盖关键词、是否必须在技术标正文中出现、建议出现频次、可关联检测/验收/留痕资料 |
| 编制调用 | 后续施组必须调用项目级关键词覆盖矩阵；每个评分章节覆盖评分关键词，每个主要工程对象至少进入工程概况、重点难点、施工方案、质量控制、安全控制、进度组织或总平面布置 |
| 表达要求 | 关键施工工艺写成“工序流程+操作措施+质量控制+验收标准+留痕资料”；风险关键词写成“风险识别+应对措施+检查频次+责任人+留痕资料”；材料参数进入材料控制、工艺控制或质量验收 |
| 禁止事项 | 不得机械堆砌关键词；禁止继续引用被答疑澄清替代的旧内容；不得把空泛口号提升为高权重；不得引入项目资料未出现且不属于本项目类别的工程对象 |

### 项目级关键词权重逻辑

| 来源或内容 | 权重等级 | 处理规则 |
|---|---|---|
| 答疑澄清、补遗变更中出现并覆盖原要求的关键词 | 最高权重 | 优先写入资料矩阵、评分响应矩阵、章节标题或段首，并删除/降级被替代旧内容 |
| 评分标准中的评分项、扣分项、页数限制、AI 辅助评审要求 | 最高权重 | 进入评分项原文锁定、最高档拆解、五锚点索引和高分理由反查 |
| 招标范围和工程量清单中的主要工程对象 | 高权重 | 进入工程概况、重点难点、施工方案、质量安全控制和验收资料 |
| 图纸中的结构参数、材料规格、断面尺寸、施工范围 | 高权重 | 进入工艺参数、材料控制、质量验收和参数证据锁 |
| 技术标准和合同条款中的强制性要求 | 高权重 | 作为强制控制标准，缺页码或条款时标 A_pending |
| 现场踏勘资料反映的施工条件、风险点、交通条件、周边环境 | 中高权重 | 进入平面布置、风险应对、安全文明、环保水保和进度组织 |
| 通用质量、安全、进度、环保管理词 | 普通权重 | 只能辅助表达，必须绑定项目对象、检查动作和留痕资料 |
| 空泛口号类词语 | 低权重或剔除 | “高度重视、科学组织、确保顺利、加强管理”等必须删除或改写为具体措施 |

### 项目级关键词覆盖矩阵调用验收

| 验收项 | 通过标准 |
|---|---|
| 评分项覆盖 | 每个评分章节均命中对应评分关键词、同义词、扣分项和证据锚点 |
| 项目对应性 | 项目名称、工程部位、清单子目、图纸参数、技术标准与资料原文一致 |
| 工艺闭环 | 关键工艺均包含工序流程、操作措施、质量控制、验收标准、留痕资料 |
| 风险闭环 | 风险关键词均包含风险识别、应对措施、检查频次、责任主体、整改复核 |
| 参数证据 | 材料、规格、工程量、强度、厚度、粒径、渗透系数、检测频次均可追溯来源 |
| 答疑优先 | 答疑澄清覆盖关键词优先写入，旧关键词不得继续作为确定性正文依据 |
| 低权重清洗 | 空泛通用词不得进入高权重标题、评分点、验收标准或证据留痕字段 |
