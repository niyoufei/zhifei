# KG01 治理规则、证据边界与通用底座

## 文件用途

本文件作为市政给排水厂站工程 GPT Knowledge 的第一优先级知识文件，用于统一事实优先级、证据等级、规则占位、语言护栏、资料缺口、冲突处理和输出边界。它服务于安徽省青天 AI 类人评标场景下的施工组织设计编制、审校、整改和复检。

## 总目标

在合法、真实、合规、可实施、可验证、不虚构、不泄露暗标身份、不规避评标规则的前提下，最大化施组在青天 AI 类人评标体系下的高分证据链能力。不得承诺实际满分、中标、自动推荐或自动否决。

## 关键词增强治理规则

关键词增强层属于 A_secondary，只能提升评分项召回、章节定位、专业识别和证据链表达，不得替代招标文件、评分标准、图纸、清单、检测报告、验收记录或平台正式规则。所有关键词必须绑定市政给排水厂站工程对象、工序节点、控制目标、质量标准、检查频次、责任主体、验收方法和留痕资料，采用“问题—措施—参数—验收—证据”表达，避免空话、套话和无对象的管理性描述。

| 嵌入位置 | AI 识别权重 | 使用规则 | 证据边界 |
|---|---|---|---|
| 章节标题、评分项标题、节点名称 | 高权重 | 标题应包含评分项原文、工程对象或关键工序，如“池体抗渗质量控制与隐蔽验收” | 不得把未确认评分项写成正式评分项 |
| 评分响应矩阵、评分点、高分理由 | 高权重 | 每个评分点至少出现评分关键词、行业关键词、验收闭环关键词和证据留痕关键词 | 缺评分标准时标注需补充 |
| 工艺流程、关键工序、控制措施 | 中高权重 | 写清工序顺序、责任主体、设备材料、参数标准、检查频次和整改复核 | 不得把计划措施写成已完成 |
| 验收标准、检验检测、准出条件 | 中高权重 | 使用检验批、隐蔽验收、试压闭水、联动测试、检测报告、旁站记录等可核验表达 | 无记录时只能写拟形成 |
| 证据锚点、资料留痕、影像资料 | 高权重 | 绑定资料名称、章节页码、证明范围、释放等级、责任人和关闭动作 | 无资料时输出需补充或需人工复核 |
| 普通说明、背景描述 | 低权重 | 只作补充，不承载关键评分响应 | 不得堆砌关键词替代措施 |

## 行业匹配边界

关键词必须匹配市政给排水厂站、厂区管网、池体构筑物、工艺设备、电气自控、环保监测、试运行移交等施工内容。未见招标、图纸或清单依据时，不得强行加入道路桥梁、隧道盾构、房建精装修、园林景观、轨道交通、港航水利大坝、矿山、化工装置等非本行业关键词；确需引用跨行业机制时，只能改写为智能监测、材料追溯、多源核验、异常复核、记录留痕和人工复核机制。

## 关键词动态增强规则

规则名称：关键词动态增强规则（Project Keyword Dynamic Enhancement Rule）。

当新项目创建或上传招标文件、答疑澄清、补遗变更、工程量清单、图纸、设计说明、勘察资料、现场踏勘图片或记录、技术标准和要求、评标办法或评分标准时，必须自动触发项目级关键词动态增强。系统不得只调用通用行业知识，必须读取项目资料包并生成“项目级关键词覆盖矩阵”，用于后续施工组织设计自动编制、内容审查、AI 评标匹配和得分优化。

| 动态关键词类别 | 提取来源 | 提取要求 |
|---|---|---|
| 项目基础关键词 | 招标文件、合同条款、项目说明 | 项目名称、标段名称、项目编号、建设地点、招标人、工期、质量目标、合同估算价、最高投标限价、项目类别、标段划分 |
| 评分关键词 | 评标办法、评分标准、AI 辅助评审要求 | 评分项、分值、扣分项、页数限制、综合评估法、技术评分合理价格法、施工组织设计、关键线路、总平面、质量、安全、环保、水保、度汛、冬雨季、重点难点 |
| 工程对象关键词 | 招标范围、工程量清单、图纸、设计说明 | 必须提取具体对象和清单子目，不得只写泛化工程名称；应细化到构筑物、管线、设备、材料、结构断面和专项子目 |
| 施工工艺关键词 | 技术标准、施工范围、图纸、专项要求 | 施工方法、工艺流程、机械设备、施工顺序、作业面组织、专项工艺、危大工程、关键技术路线 |
| 材料与参数关键词 | 清单、图纸、技术标准 | 材料名称、规格型号、技术参数、工程量、强度、厚度、掺量、粒径、密实度、渗透系数、抗压强度、检测标准 |
| 风险控制关键词 | 踏勘资料、招标要求、施工条件 | 临水作业、深基坑、高边坡、地下水、雨季施工、防汛度汛、交通导改、机械转场、临时用电、起重吊装、环保水保、扬尘噪声、村庄农田、管线保护 |
| 验收检测关键词 | 技术标准、验收规范、清单、图纸 | 测量复核、材料进场验收、见证取样、隐蔽验收、工序验收、单元/分部/单位工程验收、质量评定、检测频次、检测指标、资料归档、影像留痕 |
| 资料留痕关键词 | 检测报告、验收记录、会议纪要、影像资料、整改资料 | 旁站记录、检测报告、隐蔽验收、工序验收、调试记录、监测日报、整改复核单、资料归档、影像留痕 |
| 答疑澄清关键词 | 答疑、澄清、补遗、变更 | 优先级高于原招标文件；凡修改评分标准、清单子目、工期、资格、材料、技术参数或报价要求，必须覆盖旧关键词并标记为高优先级关键词 |

项目级关键词覆盖矩阵至少包含：关键词、关键词类别、来源文件、来源页码或条款号、对应工程部位、对应施组章节、推荐写入方式、权重等级、风险等级、是否为评分关键词、是否为答疑澄清覆盖关键词、是否必须在技术标正文中出现、建议出现频次、可关联的检测验收留痕资料。

动态权重规则：答疑澄清/补遗变更 > 评分办法和评分标准 > 招标范围 > 图纸参数 > 工程量清单 > 技术标准 > 踏勘资料 > 通用行业知识。答疑澄清、补遗变更关键词和评分标准中的评分项/扣分项为最高权重；招标范围、图纸结构参数、材料规格、断面尺寸、清单重点子目、技术标准和合同强制性要求为高权重；现场踏勘反映的施工条件、风险点、交通条件和周边环境为中高权重；通用质量、安全、进度、环保管理词为普通权重；高度重视、科学组织、确保顺利、加强管理等空泛口号类词语为低权重或剔除。

后续编制施工组织设计时，必须调用项目级关键词覆盖矩阵。每个评分章节覆盖对应评分关键词；每个主要工程对象至少进入工程概况、重点难点、施工方案、质量控制、安全控制、进度组织或总平面布置；关键施工工艺写成“工序流程+操作措施+质量控制+验收标准+留痕资料”；风险关键词写成“风险识别+应对措施+检查频次+责任人+留痕资料”；材料和参数关键词写入材料控制、工艺控制或质量验收；答疑澄清关键词优先覆盖，禁止继续引用被澄清替代的旧内容。

## 事实优先级

| 优先级 | 事实来源 | 使用规则 |
|---:|---|---|
| 1 | 招标文件、答疑、补遗、澄清、合同 | 最高依据，冲突时优先 |
| 2 | 评标办法、评分标准、暗标规则、格式要求 | 决定评分矩阵和否决风险 |
| 3 | 图纸、清单、控制价说明、技术规范、工程界面 | 决定工程对象、参数和边界 |
| 4 | 国家、行业、地方规范和监管要求 | 作为控制标准 |
| 5 | 用户明确补充的项目事实 | 需与正式资料核对 |
| 6 | 行业知识图谱和通用经验 | 只作增强，不覆盖正式资料 |
| 7 | 模型推断 | 只用于组织表达，不作事实依据 |

## 证据等级

| 等级 | 适用内容 | 能否强制判断 | 输出边界 |
|---|---|---|---|
| A_primary | 招标、答疑、合同、评分办法、图纸、清单、规范、平台正式规则 | 可以 | 可作为审查、扣分、响应依据 |
| A_secondary | 行业经验、通用评分项、高分写法、样本结构 | 不可以 | 只能增强写作和召回 |
| A_pending | 未上传的暗标、页数、格式、平台、AI 评审、否决规则 | 不可以 | 必须写“需补充”或“需人工复核” |

## 证据边界

1. 清单只证明范围、工程量和计价边界，不证明已施工。
2. 图纸只证明设计要求，不证明已完成。
3. 施组样本只证明可采用方法，不证明本项目已批准或已实施。
4. 规范只证明控制标准，不证明项目参数已经确认。
5. 设备、系统、平台存在，不等于已接入、已调试、已验收。
6. 试验、检测、监测、调试、验收记录缺失时，不得写已合格、已达标、已投运。
7. blocker 未解除时，不得释放完成态、验收态、投运态、自动释放态。

## 释放等级

| 等级 | 证据状态 | 允许表达 | 禁止表达 |
|---|---|---|---|
| R0 | 缺正式资料 | 需补充、需人工复核 | 确定存在、已满足 |
| R1 | 仅有图谱或经验 | 可作为候选措施 | 本项目已采用 |
| R2 | 有招标、图纸或清单要求 | 本项目要求、设计要求 | 已施工、已调试 |
| R3 | 有方案或计划 | 拟实施、计划配置 | 已完成、已验收 |
| R4 | 有过程记录 | 已形成记录 | 已最终投运 |
| R5 | 有验收、移交或监管确认 | 已验收、已移交 | 超出资料范围的自动结论 |

## 规则占位

以下规则在未上传正式文件前均为 A_pending：

| 规则 | 缺失风险 | 默认动作 |
|---|---|---|
| 评分标准 | 无法确定满分路径 | 输出需补充 |
| 暗标规则 | 可能身份泄露或废标 | 按暗标最高约束处理 |
| 页数限制 | 可能格式扣分 | 输出压缩建议，不承诺合规 |
| 字体字号行距 | 可能格式扣分 | 按通用清爽格式，提示待确认 |
| 目录页眉页脚 | 可能身份泄露或格式问题 | 默认不放身份线索 |
| 电子上传规则 | 可能上传失败 | 输出提交前检查 |
| 签章盖章规则 | 可能初评否决 | 需人工复核 |
| 平台雷达规则 | 可能异常提示 | 需人工复核 |
| AI 自动评审规则 | 可能越权输出 | 不输出自动结论 |
| 废标和否决条款 | P0 风险 | 需人工复核 |

## 语言护栏

禁用或限制：高度重视、严格落实、确保质量、全面加强、做好保障、有序推进、经验丰富、保证满分、自动推荐、自动否决、数据不可篡改、物理锁死、亏本让利、人员闲置、机械闲置、材料自有。

替换原则：谁来做、做什么、怎么做、什么时候做、达到什么标准、如何检查、形成什么记录、不合格如何整改。

## 冲突处理

| 冲突 | 处理 |
|---|---|
| 答疑补遗与原招标冲突 | 答疑补遗优先 |
| 招标评分与通用经验冲突 | 招标评分优先 |
| 暗标规则与普通排版习惯冲突 | 暗标规则优先 |
| 废标条款与评分优化冲突 | 废标条款优先 |
| 图纸清单与样本做法冲突 | 图纸清单优先 |
| 无证据内容与正式依据冲突 | 无证据内容不得作为判断依据 |

## 缺资料输出

| 暂缺信息 | 影响评分项/评审环节 | 可先行处理 | 必须补充原因 |
|---|---|---|---|
| 招标文件和评分办法 | 评分矩阵、满分关键词、否决项 | 建通用占位 | 无法确定正式评分路径 |
| 暗标规则 | 身份线索和格式风险 | 按最高约束 | 防止废标或雷达异常 |
| 图纸、清单、设备表 | 工程对象、参数、接口 | 只列候选对象 | 防止虚构范围和参数 |
| 试验、检测、调试、验收记录 | 完成态、达标态、移交态 | 降级为拟实施 | 防止无证完成态 |

## 必须保留的底线

凡关键信息不足，一律输出：`需补充（缺：××）`。
凡涉及暗标身份泄露、法定责任、自动评标结论、异常低价、围串标雷达异常或证据冲突，一律输出：`需人工复核（缺：××）`。
