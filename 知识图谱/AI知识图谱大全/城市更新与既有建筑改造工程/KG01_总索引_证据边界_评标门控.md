# KG01 总索引、证据边界与青天 AI 评标门控

## 用途

本文件是 GPT Knowledge 的总入口，用于城市更新、老旧小区改造和既有建筑改造工程施工组织设计的资料解析、评分响应、证据降级、暗标审校和青天 AI 类人评标适配。

目标是最大化施工组织设计在青天大模型类人评标体系下的高分和满分概率，但不得承诺、保证或暗示实际满分。实际得分取决于招标文件、评分办法、项目资料、评标委员会判断、监管规则和平台执行结果。

## 证据优先级

1. 招标文件、答疑、补遗、澄清、合同条款。
2. 评标办法、评分标准、暗标规则、格式要求。
3. 图纸、设计说明、专项设计、工程量清单、设备表。
4. 现行规范、地方导则、监管要求、审批文件。
5. 用户明确提供的项目事实。
6. Knowledge 中的节点、关系、证据锚点、blocker、close_action。
7. 系统规则、术语字典、劳动力最低配备和写作护栏。
8. 施组模板库和城市更新专项评分词库。
9. V9 全行业样本、类似项目经验、模型推断。

模型推断只能组织表达，不得替代项目事实、参数、记录、验收结论或评标依据。

## 硬性降级规则

| 缺失或风险 | 必须处理 |
|---|---|
| 缺招标文件、评标办法、评分项原文 | 输出需补充，不得生成确定性满分响应 |
| 缺图纸、清单、合同界面 | 不得确认工程范围、工程量、接口责任 |
| 缺检测鉴定、专项审批、参数表 | 不得写拆改加固结论、设备参数、资源人数 |
| 缺试验、调试、验收、移交记录 | 不得写已检测、已调试、已验收、已投运、已移交 |
| 缺暗标规则或发现身份线索 | 输出需人工复核，清理单位、业绩、人员归属、路径和元数据 |
| 缺异常低价、雷达、自动评标授权 | 不得自动推荐、自动否决或作法定结论 |
| V9 行业样本未匹配项目证据 | 只能作为候选方法和风险提示 |
| 系统规则未完成项目适用性校核 | 只能输出模板和需补充 |
| 模板库缺评分矩阵输入 | 先生成评分响应矩阵，不直接输出最终成稿 |

固定短语：

- `需补充（缺：招标文件和技术文件评分标准）`
- `需补充（缺：项目范围/图纸/清单/专业边界）`
- `需补充（缺：成员级参数/真实记录/验收资料）`
- `需人工复核（缺：自动化授权/暗标规则/异常低价规则/雷达监测依据/证据冲突）`

## 青天 AI 类人评标抽取链路

1. 解析评分项原文、分值、等级、否决项、格式要求。
2. 抽取投标文件中的响应章节、表格、关键词和证据页族。
3. 判断完整性、针对性、可实施性、合规风险和可追溯性。
4. 形成高分理由、扣分风险、需补充事项和人工复核事项。
5. 用审校整改复检闭环修正文本。

AI 友好文本必须做到：标题含评分关键词；段首直接回应评分项；一段只解决一个评分点或一个工程对象；表格字段稳定；每项措施能回到控制目标、关键工序、量化参数、验收方法、留痕资料和关闭动作。

## 关键词增强层总规则

所有知识节点、评分响应矩阵和正文模板必须建立“问题—措施—参数—验收—证据”链路。关键词不得孤立堆砌，必须嵌入标题、节点名称、工序说明、控制措施、参数标准、检查验收、风险应对、资料留痕、评标映射和输出模板示例。

| 关键词类别 | 必须嵌入字段 | AI 类人评标识别表达 |
|---|---|---|
| 评分关键词 | 章节标题、评分项原文、满分关键词、AI识别词、高分理由 | 控制目标、评分响应、针对性、可实施性、完整性、闭环性 |
| 行业关键词 | 工程对象、专业接口、行业类别、适用边界 | 城市更新、老旧小区改造、既有建筑改造、修缮、加固、管线迁改、消防机电、智慧社区 |
| 工艺关键词 | 关键工序、工序流程、操作步骤、资源配置 | 先调查后施工、样板先行、基层验收、节点加强、单机调试、系统联调、竣工移交 |
| 重难点关键词 | 风险难点、专项方案、控制重点、纠偏措施 | 既有结构不确定、居民不停住、管线交叉、消防联动、渗漏治理、隐私合规、穿插施工 |
| 风险关键词 | blocker、风险闭环、应急处置、整改复核 | 证据缺口、暗标身份、越权完成态、接口不清、停复供风险、扰民投诉、行业错配 |
| 质量控制关键词 | 质量目标、控制点、允许偏差、检验批、复验复检 | 材料复验、首件样板、隐蔽验收、功能试验、检测报告、整改闭环 |
| 安全控制关键词 | 危险源、风险等级、专项审批、安全交底、旁站监测 | 临时支撑、脚手架、吊篮、高处作业、消防通道、应急照明、监测预警 |
| 绿色施工关键词 | 环境保护、扬尘噪声、固废处置、资源节约 | 湿法作业、覆盖降尘、分类清运、消纳证明、低噪设备、节水节电、绿色施工记录 |
| 智慧建造关键词 | BIM/管综、智慧工地、物联感知、平台接入、日志 | 点位表、权限分级、网络供电、数据脱敏、平台验收、运维台账、数字化留痕 |
| 验收关键词 | 验收标准、检查频次、验收方法、移交条件 | 检验批、隐蔽验收、闭水试验、试压记录、联动调试、竣工验收、移交清单 |
| 证据留痕关键词 | 证据页族、记录表单、影像资料、报告、台账 | 旁站记录、检测报告、调试记录、整改通知、复检单、影像资料、签认记录 |
| 同义近义词 | AI识别词、召回关键词、评标常用表达词 | 检查/核查/复核，验收/检验/确认，留痕/记录/台账，整改/闭环/销项 |

## 关键词权重规则

| 出现位置 | 权重 | 使用规则 |
|---|---|---|
| 章节标题、节标题、表格名称 | 高权重 | 标题应包含评分关键词、工程对象和控制目标，如“外立面修缮质量控制与隐蔽验收留痕”。 |
| 评分点、评分响应矩阵、满分关键词、AI识别词 | 高权重 | 必须直接承接评分项原文，不改变评分项本意，补充同义词和评标常用表达词。 |
| 证据留痕、检测报告、旁站记录、整改复核、移交清单 | 高权重 | 每项措施必须能对应至少一种拟形成或已提供的资料，缺资料时写 blocker 和 close_action。 |
| 工艺流程、关键工序、控制措施、资源配置 | 中高权重 | 按施工段、楼栋、系统或界面描述动作、责任岗位、检查频次和参数来源。 |
| 验收标准、质量标准、检查方法、检验批 | 中高权重 | 写清验收方法、允许偏差或规范来源；缺实测数据时不写完成态。 |
| 风险应对、应急处置、动态优化、纠偏措施 | 中权重 | 必须有风险触发条件、责任主体、整改动作和复核节点。 |
| 普通背景描述、泛泛管理口号 | 低权重 | 不作为高分理由；凡不能连接评分点、工序、验收或证据的文字应删减。 |

权重叠加规则：同一评分关键词若同时出现在标题、评分矩阵、关键工序、验收标准和证据留痕中，可作为高置信评分命中；若只出现在普通描述中，只能作为低置信辅助信号。

## 关键词动态增强规则（Project Keyword Dynamic Enhancement Rule）

当新项目创建或上传资料包时，必须自动触发项目级关键词动态增强。系统不得只调用通用行业知识，必须先读取该项目的招标文件、答疑澄清、补遗变更、工程量清单、图纸、设计说明、勘察资料、技术标准、现场踏勘图片或踏勘记录、评标办法和评分标准，生成“项目级关键词覆盖矩阵”，再进入施工组织设计编制、内容审查、AI 评标匹配和得分优化。

触发条件：上传或更新以下任一资料即触发：招标文件；答疑、澄清、补遗、变更文件；工程量清单；图纸、设计说明、勘察资料；现场踏勘图片、踏勘记录；技术标准和要求；评标办法或评分标准。

提取逻辑：

| 关键词类别 | 提取来源 | 提取要求 |
|---|---|---|
| 项目基础关键词 | 招标文件、项目概况、合同条款 | 提取项目名称、标段名称、项目编号、建设地点、招标人、工期、质量目标、合同估算价、最高投标限价、项目类别、标段划分。 |
| 评分关键词 | 评标办法、技术文件评分标准、AI辅助评审要求 | 提取评分项、分值、扣分项、页数限制、施工组织设计、关键线路、施工总平面布置、质量保证措施、安全生产保证方案、水土保持、环境保护、安全度汛、冬雨季施工、重点难点。 |
| 工程对象关键词 | 招标范围、工程量清单、图纸 | 必须细化到清单子目、结构部位和图纸对象，不得泛化处理；例如不得只写“护岸工程”，应细化为“金属网兜抛石护岸、格网石笼、堤后盖重压渗平台、双轮铣防渗墙”等。 |
| 施工工艺关键词 | 施工技术要求、图纸说明、专项方案、踏勘条件 | 提取项目特有施工方法、工艺流程、机械设备、施工顺序、作业面组织、专项施工工艺、危大工程和关键技术路线。 |
| 材料与参数关键词 | 清单、图纸、设计说明、技术标准 | 提取材料名称、规格型号、技术参数、工程量、强度指标、厚度、掺量、粒径、密实度、渗透系数、抗压强度、检测标准。 |
| 风险控制关键词 | 踏勘资料、图纸、技术要求、合同条件 | 提取临水作业、深基坑、高边坡、地下水、雨季施工、防汛度汛、交通导改、机械转场、临时用电、起重吊装、环保水保、扬尘噪声、村庄农田保护、管线保护。 |
| 验收检测关键词 | 技术标准、质量评定、验收规范、资料要求 | 提取测量复核、材料进场验收、见证取样、隐蔽验收、工序验收、单元工程验收、分部工程验收、单位工程验收、质量评定、检测频次、检测指标、资料归档、影像留痕。 |
| 答疑澄清关键词 | 答疑、澄清、补遗、变更文件 | 优先级高于原招标文件；凡修改评分标准、清单子目、工期、资格、材料、技术参数或报价要求的，必须覆盖原关键词，并标记为高优先级关键词。 |

项目级关键词权重：

| 来源或词类 | 权重 |
|---|---|
| 答疑澄清、补遗变更中出现的关键词 | 最高权重 |
| 评分标准中的评分项和扣分项 | 最高权重 |
| 招标范围和工程量清单中的主要工程对象 | 高权重 |
| 图纸中的结构参数、材料规格、断面尺寸、施工范围 | 高权重 |
| 技术标准和合同条款中的强制性要求 | 高权重 |
| 现场踏勘资料中的施工条件、风险点、交通条件、周边环境 | 中高权重 |
| 通用质量、安全、进度、环保管理词 | 普通权重 |
| 高度重视、科学组织、确保顺利、加强管理等空泛口号 | 低权重或剔除 |

项目级关键词覆盖矩阵字段：

`关键词 | 关键词类别 | 来源文件 | 来源页码或条款号 | 对应工程部位 | 对应施组章节 | 推荐写入方式 | 权重等级 | 风险等级 | 是否为评分关键词 | 是否为答疑澄清覆盖关键词 | 是否必须在技术标正文中出现 | 建议出现频次 | 可关联的检测、验收、留痕资料`

施组调用规则：后续自动编制施工组织设计时必须调用项目级关键词覆盖矩阵。每个评分章节必须覆盖对应评分关键词；每个主要工程对象必须至少进入工程概况、重点难点、施工方案、质量控制、安全控制、进度组织或总平面布置；关键施工工艺必须写成“工序流程+操作措施+质量控制+验收标准+留痕资料”；风险关键词必须写成“风险识别+应对措施+检查频次+责任人+留痕资料”；材料和参数关键词必须写入材料控制、工艺控制或质量验收；答疑澄清关键词必须优先覆盖，禁止继续引用被澄清替代的旧内容。

AI 评标优化目标：评分项全覆盖；项目名称、工程部位、清单子目、图纸参数一致；施工措施具体、可执行、可检查；风险识别对应现场；质量、安全、环保、进度均有量化指标；每项关键措施均有验收标准和资料留痕；避免通用模板化、空泛化和其他项目残留；提高青天大模型 AI 类人评标下的关键词命中率、响应完整度和技术标得分。

## 评标办法适配

| 评标办法 | 施组重点 |
|---|---|
| 动态合理价格法 | 初评合格、无漏项、无暗标格式风险、无工期质量安全冲突 |
| 技术评分合理价格法 | 逐项形成高分理由，支撑技术排名靠前 |
| 综合评估法 | 技术、商务、报价不矛盾，技术措施不降低设计标准和报价合理性 |
| 定性定量评审法 | 支撑“好”或最高等级评价，避免一般化和低密度表达 |

无法确认评标办法时，输出 `需补充（缺：评标办法和技术文件评分标准）`。

## 评分响应矩阵字段

`序号 | 评分项原文 | 分值/等级 | 标题关键词 | 满分关键词 | AI识别词 | 行业关键词 | 工艺关键词 | 重难点关键词 | 风险关键词 | 质量控制关键词 | 安全控制关键词 | 绿色施工关键词 | 智慧建造关键词 | 验收关键词 | 证据留痕关键词 | 同义近义词 | 招标证据页族 | 工程对象 | 响应章节 | 控制目标 | 关键工序 | 执行措施 | 资源配置 | 量化参数 | 检查频次 | 验收方法 | 留痕资料 | 风险闭环 | blocker | close_action | 复检状态`

规则：

1. 评分项原文不得随意改写。
2. 每个评分项至少绑定一个工程对象、一个章节、一组关键词增强层、一组措施、资源、参数来源、验收方法、留痕资料和风险闭环。
3. 缺证据时写 blocker 和 close_action，不补造事实。
4. 涉及行业能力时先路由到 KG02，再由项目证据决定是否释放。
5. 涉及正文生成时交给 KG03 模板化输出。
6. 涉及城市更新专项召回时调用 KG04。
7. 同义近义词仅用于提升召回，不得改变工程对象、施工内容和证据边界。

## 审校风险矩阵

`风险类型 | 位置 | 问题 | 触发规则 | 影响 | 修改建议 | 是否需人工复核`

必须覆盖：初评否决、暗标身份、评分漏项、证据缺口、越权完成态、异常低价禁用理由、自动释放越权、低密度套话、项目残留和行业错配。

## 禁止事项

不得为追求满分虚构项目事实；不得把清单、图纸、规范或样本写成真实完成记录；不得隐藏待补事项；不得在暗标技术标中出现身份线索；不得输出保证满分、必得满分、已满分覆盖、自动否决、自动推荐、无需人工复核等无证据或无授权结论。
